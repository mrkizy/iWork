# ADR-T04p-a 发布包由「打包之后装配」做成，不用打包器的 sidecar；验过才发布

- 状态：提议（2026-11-13，T04p；编号由 supervisor 合入时统一）
- 依据：T04p 方案（`docs/plans/T04p.md`）第 3、4 节与第 15 节；T04 方案 2.9（完成依据与两种包形态）；T03 方案 2.4、2.4a；`docs/design/t0-findings.md` 7.1（N5）

## 背景

发布包里要有后台程序。无证书的包要带一份清单，登记两个程序的身份；有证书的包要整包签名，而且不能有清单。

- 清单必须在所有会改文件的步骤之后写；
- 封印必须在所有放文件的步骤之后做；
- 包的形态齐，不等于装上之后两个程序能互认。ad-hoc 签的整包形态齐、验签也过，但没有证书也没有清单，两端认不上。

T04 的 N5 在真实包上把前两条次序量过，当时是手工拼的包。

## 决定

`pnpm -C client tauri build` 里，Tauri 只把客户端打成 `.app`（Linux 不打包）。之后由仓库自己的装配脚本 `scripts/assemble-release.sh` 放后台，再写清单或签名。

装配和核对都在暂存目录里做。核对用运行时的同一段代码问三件事：

- 恰好一种形态成立（`install::forms`）；
- 包里两个程序按信任规则能互认（`peer::file_signer` 加 `judge_peer`，两个方向各判一次）；
- 有证书时，两个程序都是预期的那张证书签的。

三件都过才改名发布到 `<输出根>/release/dist/`。核对失败或被中断，成品路径上原来的包不动。

签名只在装配步骤里做。装配读的每个文件都来自这一次构建，位置由 cargo 报出来。

## 备选

- **`bundle.externalBin`**：各种安装包格式能自动带上后台。但下面这些都落在打包器没实测过的行为上：清单与成品是否一致、签名次序、两种形态怎么分配置、对平时编译有什么影响。M1 也用不上那些格式。否决。
- **让 Tauri 签名、装配后再重签**：同一件事做两遍，先签的那一遍只会碍事。否决。
- **把后台直接放进 Tauri 的输出目录**：中间产物和成品同一条路径，失败时分不清是哪一个。否决。
- **只判「形态齐」**：ad-hoc 整包签名的包会被放过去，装上之后两端互不相认。否决。

## 影响

- M1 不出 `.dmg` 与 Linux 安装包（PD-1）。
- `tauri build` 不再接受 `--bundles`、`--no-bundle`、`--target`、`--debug`、`--runner`、`--features`，以及 `--` 之后转给构建程序的参数。
- 成品在 `<输出根>/release/dist/`。形态由 `IWORK_SIGN_IDENTITY` 选，身份是 `-`（ad-hoc）或空值时拒绝。
- 以后要出别的格式，照方案 8.3 先实测再换办法；核对那一段不变。
- `peer` 多一个只读函数 `file_signer`，信任判定不变。
