# ADR-T07-d 路径目标取「链接本身」与「解析后目标」两种视图，都过底线；不按程序登记链接语义

- 状态：已采纳（2026-11-10，T07 收口；产品负责人批准，编号合入时由 supervisor 统一）
- 依据：`docs/plans/T07.md` 2.3、3.1、3.5、4.3、第 13 节收口行、第 16 节

## 背景

一条命令遇到链接时到底动哪里，取决于程序、选项和平台：`cp` 写穿，`mv` / `ln` / `install` 换掉目录项，`rm 链接/` 删的是目标目录。第 8 轮按程序登记「写穿 / 替换目录项」，第 9 轮同一类问题从四个入口再冒出来（尾斜杠、`install` 登记反了、没登记的操作、受保护路径自身是链接）。`.git` 内部与关键路径没有沙箱兜底，登记错一格就是底线漏判。

## 决定

1. `PathResolver::resolve` 一次返回 `ResolvedPath{entry, target}`：`target` 完全解析，`entry` 末级不跟随；带尾斜杠、末级是 `.` / `..`、单独的 `~` 时两者相同（`iwork_ports::fs::split_last_component` 一处定）。
2. 读、写、删的每个路径动作两种视图各出一个动作（`paths::views` 一处真值，先 `entry` 后 `target`，相同时一个），任一命中底线或越界就按命中处理，不按程序分、不分读写。
3. 解析失败分两类，`PathResolveError::certainty()` 一处给出：走不通（`NotADirectory`、`..` 在不存在的分量之后）——真实目标整条解析不了、候选只丢它；查不清（权限、链接成环、非 UTF-8、`~其他用户`、其他 I/O 错误）——打 `ActionFlag::PathUnresolved`，命中 `UserDeny` 层内置条目 `deny.path-unresolved`，三档拒、不出卡片。
4. 规则路径同时守原位置与解析后位置：会话启动时 `session::rule_paths_for` 对保护性条目（底线拒绝类、敏感目录、自动执行配置）取解析事实，`snapshot_for` 按事实生成别名条目；只读区放行、可写缓存、可写目录不生成别名。事实写进 `SessionSnapshot.rule_paths` 与每条 `ApprovalEvaluated.snapshot_rule_paths`，重放只用事件里的映射、不读磁盘。

## 备选及放弃原因

一律跟随（第 7 轮及以前：换掉 `.git/hooks` 里的链接、换掉链接形态的凭据文件都漏判）；按程序登记 `WriteMode`（第 8 轮：组合写不全）；只对「写穿」类查两种视图（仍要登记谁是写穿）；规则别名只放内存（用户改链接后重放得不到当时的规则集）。

## 影响

换掉、删掉一个本身指向受保护位置的链接会被拒（实际只动链接本身），照着凭据目录里的链接去读也被拒，单条命令走亲手执行卡片；经链接读写算两个动作，只能允许一次；路径查不清的调用三档拒、用户批不了；以后加程序不用再登记链接语义。每条审计事件多一两百字节。
