# ADR-0009 制品的「有无引用」由投影表从事件推导，最终判断与删除和引用提交同一串行边界

- 状态：已采纳（2026-11-10，T02）
- 依据：方案 `docs/plans/T02.md` 2.10、第 12 节；技术设计 5.4；需求 v1.68

## 背景

设计 5.4 说「引用计数在数据库里，定期回收无引用对象」，`ArtifactStore` 有 `retain/release`。但写对象与提交引用它的事件不在同一事务，纯计数在崩溃时会算错；回收与新引用、再次写入同内容之间还有竞态。

## 决定

- `artifact_refs` 是投影表：投影器从带 `ArtifactRef` 的事件加行（穷举 `match`，与「把事件编成 proto 后递归扫描」的对拍测试互相看守），对应实体被删时级联删行，随投影重建。
- `retain/release` 只维护 `artifact_objects.pins`（显式 pin）。
- 写入：临时文件 → fsync → **先**在写线程登记或刷新 `created_at` → 再改名到哈希路径；同哈希再次写入也刷新，重新获得一整个宽限期。
- 回收条件 = 无 `artifact_refs` 行 ∧ `pins = 0` ∧ 过了宽限期（默认 24 小时）。读侧只做预选；复查、删行、删文件都在写线程的同一个事务里，与引用提交、pin、再次写入串行。运行中不扫目录。
- `tmp/` 半截、有行无文件、有文件无行三类残留只在启动恢复（`FsArtifactStore::recover`，任何写入与投递开始之前）清理；有行无文件但仍被引用的只记错误日志（内容已丢，已知限制）。
- 三个区（`artifacts/`、`attachments/`、`private/`）三个目录，不跨区去重；新文件 0600、目录 0700。

## 备选

- 只用 `retain/release` 计数：崩溃算错、不可重建。
- 只用宽限期：删除对话后的副本要等宽限期，且没有可审计的引用关系。
- 读侧选完直接删：选中之后才来的引用挡不住。

## 影响

- 加带 `ArtifactRef` 的事件要在 `projector/artifact_refs.rs` 的穷举 `match` 补一行（漏了编译不过，对拍测试也红）。
- GC 占用写线程的时间与候选数成正比，一次最多处理 `max_batch` 个候选；app 可以不调 `retain/release`。
