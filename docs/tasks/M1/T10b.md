# T10b 助手与私聊

> 从 T10 拆出（产品负责人 2026-11-10 同意拆卡）。范围和验收照搬 T10 原文，保留原编号；拆卡时新加的条目都注明来源。

- **风险**：中
- **依赖**：T10a
- **依据**：M1 技术设计 9.1、9.1a、9.0a；需求 FR03、FR05、FR18、AC21、AC40；T09 方案第 3 节 G1、G7、G8

## 目标

用户能管理助手，能和每个助手私聊；私聊里切换项目时，工作目录和审批规则跟着换。

## 范围

**做**

0. **助手管理（最小）**（原范围 0，9.1a）：新建、编辑（名字、头像、提示词、运行时、工具开关；子代理始终可用，不提供开关）、删除（9.1a，不提供停用）；iWork 不可删除，可以重置为内置默认配置（`ResetAssistant`，需求 AC21）。
1. **助手私聊**（原范围 1，9.1、6.4）：每个助手一条 `assistant_dm` 对话；项目选择器列出全部项目和「私聊」（M1 没有团队）；每条消息记 `context_project_id`，切换时生成「切换到 X」分隔事件；底层按「助手 × 项目」各开一条 CLI 会话线，切换项目时工作目录、AGENTS.md、审批规则随之切换，其他项目段的内容不带入；「私聊」的工作目录是 `~/iWork/assistants/<助手名>/`（不在数据目录里，见 M1 技术设计 9.1），任何仓库都算工作区外。内置助手 iWork 存在且不可删除（AC21）。
2. **对话标题与重命名**（拆卡时补，T09 G1、技术设计 9.0a）：填 `Conversation.title` 和 `title_source`；受理 `RenameConversation`；新加事件 `ConversationRenamed`，连同 domain 变体、convert、`routes_for`、投影（title 列）、金样本。新事件种类按 PD6 算不可退的版本。T09 的 `rename_refreshes_sidebar` 原来用测试场景，这里换成真事件。
3. **助手最近动态与对话列表**（拆卡时补，T09 G7、G8）：`ListAssistantsResult.activities` 按「等你处理 > 运行中 > 最近一条发给用户的消息」取一条；`ListConversations` 支持筛选和分页。

**不做**：多成员、转交 iWork 的跨助手协作（M2）、记忆写入。

## 验收标准

1. 助手管理（原验收 1a）：新建的助手出现在侧栏并有私聊目录；禁用某个工具后，这个助手的会话里不出现该工具，强行调用被拒绝；删除后按 AC40 验收；iWork 无法删除。
2. 助手私聊（原验收 2）：切换项目后，新回合的工作目录和审批规则是新项目的；其他项目段的内容不出现在新会话的输入里；选「私聊」时写任何仓库都触发询问。
3. 标题（拆卡时补）：首条消息生成标题、可以重命名、私聊标题固定（FR18）；重命名后侧栏经真事件刷新。
