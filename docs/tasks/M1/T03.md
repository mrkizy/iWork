# T03 本机通信：传输、身份校验、帧、订阅、背压

- **风险**：高（安全边界：本机 IPC 不可被冒用）→ 先出方案 `docs/plans/T03.md`
- **依赖**：T01
- **依据**：M1 技术设计第 3 节全部；需求第 11 章（本机 IPC 须端点鉴权）

## 目标

实现 `iwork-ipc`：客户端与后台服务之间的本机专线，只允许同用户、同签名的进程连入；事件可按序号续传、不丢不重；慢客户端不拖垮后台服务。

## 范围

**做**

1. 传输 trait（连接、对端身份、收发帧），本机实现：macOS / Linux Unix domain socket，Windows 命名管道（路径、权限见 3.1；macOS 路径长度启动时校验）。
2. 对端校验（3.2）：同用户 + 同签名；不通过断开并记审计。`--dev-trust` 只在 `dev` feature 下编译进来，发布构建里不存在（用编译期检查证明）。
3. 帧编解码（3.3）：长度上限 4MB，`Chunk` 分片 ≤ 1MB；握手与版本协商。
4. 订阅与续传（3.5）：`Subscribe{scope, from_seq}`；先补发再切实时；`from_seq` 太旧返回快照 + 快照 `seq`；流式增量带 `(message_id, offset)`。
5. 背压：每连接有界队列（默认 8MB），满时合并同一消息的相邻文字增量，仍满则标记“落后”并通知客户端重订阅；持久事件永不丢弃。
6. 远程预留：只保留 trait，不实现。

**不做**：客户端界面状态（T09）、后台服务拉起（T04）。

## 交付物

`iwork-ipc` 及测试；一个命令行调试客户端（开发用，`dev` feature），可订阅并打印事件。

## 验收标准

1. 不同用户连接被拒（Linux CI 以另一个用户身份连接；做不到的平台对判定函数做单元测试并在报告说明）。
2. 签名或哈希不符的可执行文件连接被拒；发布构建中搜索不到 `dev-trust` 相关符号（检查命令写进 CI）。
3. 超过 4MB 的帧、畸形帧、未握手先发请求均断开且后台服务不崩溃（模糊测试 `cargo fuzz` 至少跑通一个目标）。
3a. 握手按协议主版本两个方向都拦（技术设计 3.3，产品负责人 2026-11-09 决定）：旧客户端 × 新后台、新客户端 × 旧后台都被拒绝，错误里带双方主版本号，拒绝前不处理任何业务帧；同主版本、不同次版本照常连通。
4. 断线续传 proptest：随机断线、随机重连点，客户端最终收到的持久事件序列与服务端完全一致，无缺无重。
5. 慢消费者：一个客户端停止读取时，另一个客户端的推送延迟不受影响；停止读取的客户端被标为落后，恢复后重订阅拿全事件。
6. socket 所在目录权限 0700（Windows 为仅当前用户的 DACL），有测试检查。

## 注意

- iWork 自己的进程不开任何 TCP 端口，包括调试模式与 `--dev-trust`。开发期前端工具链（`tauri dev` 的 Vite 开发服务器）的约束见 `AGENTS.md` 安全不变量。
- 审计日志不记录消息内容。
