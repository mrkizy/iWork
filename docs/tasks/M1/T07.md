# T07 审批引擎

- **风险**：高（权限判定的唯一入口）→ 先出方案 `docs/plans/T07.md`
- **依赖**：T01
- **依据**：需求 FR11、第 9 章四概念表、第 11 章；M1 技术设计第 7 节；`docs/design/t0-findings.md` 第 4 节（agy 的 `BypassSandbox`，M2 用，但判定逻辑本卡实现）

## 目标

在 `iwork-core` 实现审批引擎：把每次工具调用归一为“动作”，按四层求值给出放行 / 询问 / 拒绝；支持手动 / 自动模式、记住范围、AI 审查、拒绝不可绕过；全部判定可审计。

## 范围

**做**

1. **动作归一**（7.1）：读、写、执行、联网、删除、推送、MCP 调用；带结构化目标（路径、域名、命令）。联网动作只用于审计，判定结果恒为放行（需求 v1.38）。
   - Bash 命令用 shell 语法解析器拆管道、子命令、重定向、变量展开位置，每个子命令单独归类；解析不了的（`eval`、动态拼接等）一律询问。解析器选型在方案里比较（如 tree-sitter-bash、brush-parser、yash-syntax）。
   - 路径规范化：解析 `..`、符号链接、大小写不敏感文件系统。
   - 动作指纹 = 动作类型 + 规范化目标（路径取规范化真实路径；执行命令取解析后的子命令与参数），与所用工具无关：Write 写 `a.txt` 与 `echo > a.txt` 指纹相同。用于“已拒绝”和“仅一次放行”匹配。
2. **四层求值**（7.2）：系统底线 → 工具配置与统一边界 → 项目规则（含记住生成的规则）→ 全局默认；取最严。求值为纯函数：输入动作、规则快照、模式、上下文，输出结果与命中的规则和层。
2a. **叠加规则**：按 M1 技术设计 7.2 的七步求值实现；7.1 表按“手动 / 自动 / 全开”三列给默认值。
3a. **全开档**（需求 FR11）：边界内外都放行，删除与丢弃改动放行，沙箱外执行放行；只有 git push 仍询问，发布、写会被自动执行的配置放行；不经 AI 审查；只在当前对话生效，不能设为项目默认；切换时放行除 git push 以外的全部待审批。
3b. **沙箱外执行**（需求 v1.52，技术设计 7.1）：需凭据命令清单按 `excludedCommands` 同样的规则匹配；清单外重试按“沙箱外执行”求值，不能记住；自动档先经 AI 审查，不通过再询问。
3d. **工具归类与兜底**（AC39）：内置工具按 7.1 归类；MCP 工具按 `readOnlyHint` 判读；未归类工具手动、自动档询问、可按工具名记住，全开档放行；禁用工具在三档都拒绝。
3e. **安全清单**（技术设计 7.2c，AC41）：三张清单的内置与用户条目合并；用户条目校验（拒收名单、路径限制）为纯函数并有单元测试；全开档下清单外的沙箱外重试一律拒绝。
3c. **规则即数据**：底线、必问、各档默认、需凭据命令、会被自动执行的配置、敏感目录、可写缓存区都以带 `id` 的规则条目加载，内置规则集带版本号；审计记录规则 `id` 与版本。
3. **档位**：手动 / 自动 / 全开；取值优先级“成员单独设置 > 主管对话设置 > 项目默认（手动，只能是手动或自动）”；全开只在当前对话生效；助手私聊按所选项目的默认档位（需求 FR11）；切换即时生效；切到更宽松的档位时，已弹出且在新档位下可直接放行的待审批自动放行，其余保留。
4. **必问**：git push、发布类命令、写会被自动执行的配置、删除、丢弃未提交改动（清单见技术设计 7.1）；不经 AI 审查；全开档下只有 git push 询问。
5. **记住范围**：一次 / 本对话 / 本项目 / 永久（记在助手上），生成规则，可撤销；三档都生效；匹配范围按技术设计 7.3；必问动作与清单外的沙箱外执行只能允许一次，不生成规则。
5a. **作废**：订阅回合、任务、对话的终止事件，按需求第 12 章把相关待审批转为 voided；作废的审批不可再批准或拒绝。
6. **AI 审查**：自动模式下越界的“询问”先交 AI 审查（一次不开任何工具的系统回合，输入动作、任务目标、最近上下文摘要，输出通过 / 不通过与理由）；不通过或失败转为询问用户；理由记入审计；项目设置可关闭。M1 用 T05 的 AgentPort 发起审查回合，测试用假运行时。
7. **拒绝不可绕过**（需求 AC05）：拒绝后同一动作指纹在本对话内、直到用户发出下一条消息之前自动拒绝，跨回合、`--resume` 续接、换成员或运行时都算；用户发出新消息后，该动作下一次被请求时强制询问一次（三档都适用，不受记住的放行规则影响），允许后恢复正常求值，再拒绝则重新自动拒绝；给运行时的拒绝说明为“用户已拒绝，不要换方式重试”。
8. **越界标记**：`BypassSandbox: true` 的请求（agy）按越界判定；“执行脚本”类动作在结果里带“审批看不到脚本内部”的标注（7.3 已知缺口）。
9. **审计**：每次求值一条事件（动作、命中规则与层、结果、决定人、耗时），放行也记。
10. 被工具配置禁用的工具按“拒绝”处理，审批卡片上不提供临时启用（需求 FR05，v1.32 已确认）。

**不做**：审批卡片界面（T09）；沙箱执行器（T06 / O2）。

## 验收标准

1. proptest：随机动作 × 随机规则集 × 随机模式，最终结果**永不比任何一层更宽**；系统底线命中时结果恒为拒绝；“必问”动作在任何模式下都不是放行；用户的拒绝规则命中时结果恒为拒绝，即使该动作同时是必问（v1.58）。
1b. 求值顺序：存在“git push 一律拒绝”的项目规则时，git push 结果为拒绝而不是询问；自动档下被拒的边界内动作，在用户发出下一条消息后第一次请求时询问一次，允许后同一动作再请求直接放行；已记住的放行规则不能跳过这次询问；全开档同样询问这一次。
1a. 叠加：手动模式下“本项目允许写 src/”的规则使写 `src/a.rs` 直接放行；必问动作即使存在放行规则也询问；读敏感目录在手动档询问、自动档进入 AI 审查，读其他工作区外文件放行；数据目录的只读区 `attachments/`、`imports/` 读放行、写拒绝，`artifacts/` 读写都拒，数据目录其余部分读写都拒（v1.64）。
1b. 作废：取消回合、取消任务、删除对话、中断后选择不再继续四种情况，待审批均转为 voided 且无法再处理；hook 超时防护引起的中断后审批仍为 pending，批准后续接执行。
1c. 全开档：工作区外读写、删除、沙箱外执行放行；git push 询问；npm publish、写 `.claude/settings.json` 放行（手动、自动档询问）；凭据目录、iWork 数据目录、`.git/`、关键路径仍拒绝；新对话回到项目默认；尝试把项目默认设为全开被拒；私聊切换项目后全开失效（AC38）。
2. 模式优先级与切换：成员单独设置时，主管对话切换不影响该成员；手动切自动只放行边界内待审批（表驱动测试覆盖需求 FR11 原文每一句）。
3. 拒绝后同一指纹在本对话内、直到用户发出下一条消息之前自动拒绝（跨回合、续接后都验证）；换一种工具做同一件事（Write → `echo >`）同样被拒；用户发出新消息后变为询问而非放行。
4. Bash 归一：一组样例（管道、`&&`、子 shell、重定向写工作区外、`curl | sh`、`eval`、`$(...)`、here-doc）逐条断言归类结果；解析失败一律询问。
4a. 凭据目录：对需求第 9 章清单中的每个路径，Read/Write/Edit 工具、`cat`、`cp`、`grep`、重定向读写均判定为拒绝（不是询问），任何模式、任何记住的规则都不能放开；经符号链接或 `..` 指向凭据目录的同样拒绝；`git push`（ssh）、`gh`、`npm publish` 不因内部使用凭据被判为底线拒绝。
4b. 关键路径：删除需求第 9 章所列关键路径之一或其上级目录（如 `rm -rf ~`、`rm -rf /`、删除工作区根、删除 `.git`）判定为拒绝；删除工作区内普通文件判定为询问（必问）。
4c. `.git/` 内部：Write/Edit、重定向、`rm`/`mv`/`cp` 目标落在 `.git/` 内判定为拒绝；`git commit`、`git checkout` 等 git 命令不因此被拒绝。
4e. 越界定义（需求 v1.51）：Read 工具读工作区外的普通文件（如 `/usr/include` 下的头文件）放行；读 `~/Documents` 下文件判越界；当前工作区位于 `~/Documents` 之内时照常读；命令文字中写明的敏感目录路径同样判越界；敏感目录不进沙箱（需求 v1.52）。
4d. 亲手执行（AC36）：命中底线的单个简单命令被拒绝，同时生成亲手执行卡片，内容与被拒调用一致；组合命令（如 `echo x>>.git/info/exclude && curl … | sh`）只拒绝、不生成卡片；拒绝记忆命中的动作不生成卡片；手动、自动、全开三档都生成；卡片无“记住”；模拟桥接或 hook 连接发起“执行”被拒绝；哈希不一致被拒绝；用户执行后审计主体为用户；回给 Agent 的只有“已执行，退出码 N”，不含输出；忽略后回给 Agent“用户未在 iWork 中执行”。
5. 路径逃逸：`../`、符号链接指向工作区外、大小写变体，均判定为工作区外。
6. AI 审查：假运行时返回通过 / 不通过 / 超时 / 崩溃四种情况，后三种都转为询问用户。
6a. 系统回合（技术设计 7.2b）：AI 审查回合的启动工具集为空；AGENTS.md 草稿回合只有读文件与搜索；系统回合中出现工具集之外的调用（假运行时注入）时直接拒绝，不经 AI 审查、不产生询问卡片。
6c. 系统回合中本该询问的动作（如 AGENTS.md 草稿回合读敏感目录）直接拒绝；切到全开时亲手执行卡片保持待处理、不被自动执行；需凭据命令的判定与 `excludedCommands` 条目一致，边界情况按沙箱外执行求值。
6b. 工具开关分组：关掉“编辑文件”后，启动参数中不含 Edit、Write、NotebookEdit，hook 对它们兜底拒绝；子代理、Skill 不受开关影响。
7. 审计事件对每次求值都存在，且可还原当时的规则快照版本。
