# T06 Claude Code 自写适配器（`iwork-bridge-claude` + `iwork-claude-hook`）

- **风险**：高（审批不可绕过的关键一环；实测发现 hook 超时即放行）→ 先出方案 `docs/plans/T06.md`
- **依赖**：T05（审批判定先用桩，T07 完成后接真实引擎）
- **依据**：M1 技术设计 6.3、6.4、9.4、Q3–Q6；`docs/design/t0-findings.md` 第 2 节（**以它为准**）；`tools/t0/iwork-t0*.sh`（实测方法可复用）
- **未决事项**：README 中 O1、O4（O2 已决定：M1 不做 iWork 沙箱执行器）

## 目标

后台服务经 ACP 驱动用户本机的 Claude Code：流式输出、工具活动、用量与额度上报、会话续接都可用；每一次工具调用都先经 iWork 审批，且在任何超时、断线、崩溃情况下都不会默认放行。

## 范围

**做**

1. **桥接进程** `iwork-bridge-claude`：ACP agent 端（stdin/stdout）↔ Claude Code CLI。
   - 启动：`claude -p --input-format stream-json --output-format stream-json --verbose`，加模型、追加系统提示、MCP 配置、`--settings <生成的设置文件>`、`--resume <session_id>`。
   - 每个成员会话一个常驻 CLI 进程，多轮经 stream-json 输入；进程退出后用 `--resume` 续接。
   - 转换：ACP 用户消息（文字、图片、resource_link）→ CLI 输入；`system/init`、`assistant`、工具结果、`result` → ACP `session/update`；`result` 用量 → 用量事件；`rate_limit_event` → 额度事件。
   - 取消：ACP `session/cancel` → 中断 CLI；3s 未结束交 T05 的监管结束进程树。
2. **hook 程序** `iwork-claude-hook`：Rust 单文件小程序，经 `--settings` 注入为 PreToolUse hook（匹配全部工具）。
   - 经本机 socket 把工具名与参数交给桥接，桥接发 ACP `session/request_permission`，等待判定。
   - 通道鉴权按 M1 技术设计 6.3 第 4 条：先绑定再启动 CLI、0700 目录与随机文件名、一次性令牌经环境变量传递、hook 校验对端进程号、桥接校验令牌；任一失败即拒绝。Claude Code 是否把自身环境变量传给 hook 子进程，T0 未专门验证，实现时先测；若不传，改为写进生成的会话设置文件（`run/` 下、权限 0600、会话结束即删），作为 hook 的命令行参数传入。
   - 连不上桥接、桥接返回异常、解析失败：一律返回 deny（失败即关闭）。
   - 返回格式按 t0-findings 2.1（`hookSpecificOutput.permissionDecision`、`updatedInput`）。
3. **超时防护（必须）**：hook 的 `timeout` 设为允许的最大值（O4，先用已验证的 7200 秒）；桥接为每个待审批请求计时，到时前留足余量（方案里定，建议 ≥ 60s）主动给 hook 返回 deny 并中断回合；审批仍保持待处理，用户之后批准时用 `--resume` 续接，并让被批准的动作在续接后的首次请求中放行（指纹匹配、仅一次）。续接时给模型的说明文字在方案里写出。
4. **命令改写通道**：hook 可返回 `updatedInput` 改写 Bash 命令。本卡实现改写通道与“沙箱执行器”接口（输入命令、工作区，输出包装后的命令）；执行器的具体实现见未决事项 O2，M1 默认用“不改写”实现。
5. **固定沙箱（O1）**：按技术设计 7.0 由抽象约束生成 Claude Code 的 `sandbox` 设置：底线部分三档相同，手动、自动档用写白名单，全开档放开写白名单并关闭沙箱外重试（需求 v1.65）；档位切换后下一次启动或续接会话时使用对应配置；需凭据命令清单写入 `excludedCommands`；清单外命令带 `dangerouslyDisableSandbox` 的重试照常经 hook 审批（归为“沙箱外执行”）。方案阶段先完成 O1 实测，结论与需求不符的交产品负责人决定。
5c. **禁用工具**（技术设计 7.1 内置工具归类，v1.55）：启动参数用 `--disallowedTools` 去掉创建云端定时任务或远程会话的工具与会话内定时工具；hook 对这些工具兜底拒绝。方案阶段导出固定版本的完整工具清单，逐个对照 7.1 归类，未归类的列出交产品负责人。
5d. **会话工具集**（技术设计 7.2b）：启动参数按编排核心给出的工具集传 `--tools` / `--disallowedTools`；实测两种参数在固定版本中的行为（白名单是否包含 MCP 工具、与 `--disallowedTools` 同时使用时的优先级），选定一种写进方案。
5a. **配置隔离**：按 M1 技术设计 9.5 拼装启动参数（或专用配置目录），iWork 的 hook、协作 MCP 与导入的 MCP、技能、插件按会话显式提供。
5b. **模型与思考强度**（技术设计 9.6、O10）：每次启动与续接都显式传模型与思考强度；实现对话中途改选（下一轮生效）；从 `system/init` 取实际模型上报给后台服务；提供可选模型列表与思考强度可选值。
6. **登录与版本**：`claude auth status` 只取 `loggedIn`、`authMethod`、`subscriptionType`、`loginExpiresAt`（**邮箱等字段不落盘、不进日志**）；未登录时打开 Claude Code 自己的登录流程；`claude --version` 记入运行时登记。
7. **兼容测试**：用实测时本机能装到的版本（基准随实际版本走，T0 关键结论由实测脚本复核；产品负责人 2026-11-10 定，T06 方案 P1）的真实 CLI 录制若干会话样本（含工具调用、拒绝、`rate_limit_event`、`--resume`），回放测试桥接的转换；样本先脱敏。

**不做**：审批判定规则本身（T07）；界面（T09）。

## 交付物

两个二进制、生成设置文件的逻辑、录制样本与回放测试、`docs/plans/T06.md`、O1 实测脚本。

## 验收标准

1. **不可绕过**：在用户全局权限模式为 auto、且用户设置里放行了 Bash 的环境下，iWork 判定 deny 的命令不执行（真实 CLI 集成测试，可在本机运行，报告附输出）。
2. **超时故障注入**：把 hook timeout 配成很小的值（如 10s），审批迟迟不答复：命令**不执行**；回合被中断；用户随后批准后经 `--resume` 续上并执行该动作一次。
2a. **子代理同样受审批**：让 Claude Code 通过子代理执行一条被 iWork 拒绝的命令，命令不执行；子代理内每次工具调用都触发注入的 PreToolUse hook（T0 未测，若不成立立即上报 supervisor）。
3a. **通道不可冒充**：另一个进程抢先占用 socket 路径（桥接应中止）、对端进程号不符、令牌错误或缺失、其他用户连接，四种情况下命令都不执行；日志中检索不到令牌。
3. **失败即关闭**：hook 运行时桥接 socket 不存在、桥接崩溃、返回乱码三种情况，命令都不执行。
4. 拒绝后同一动作在本对话内、直到用户发出下一条消息之前再次请求被自动拒绝，包括超时防护中断后经 `--resume` 续接的回合（与 T07 联调后验证；之前用桩验证通道）。
5. 录制样本回放：转换出的 ACP 更新序列与快照一致；`rate_limit_event` 被转换为额度事件（窗口类型、使用率、重置时间）。
6. 日志与数据库中检索不到 `claude auth status` 的邮箱字段（用含假邮箱的样本测试后 grep）。
7. hook 程序的冷启动时间与体积写进基准（数值记入报告）。
7a. 隔离：在用户配置了 SessionStart hook、全局 MCP、全局技能、auto 权限模式的环境下，iWork 会话的 `system/init` 中看不到这些（MCP 只有 iWork 注入的），用户 hook 未触发，`permissionMode` 为 iWork 设定的值；iWork 注入的 hook 仍然运行。
7b. 模型（AC37）：改选模型后下一轮 `system/init` 报告新模型，进行中的一轮不变；思考强度参数生效（以录制样本为证）；选择无权限或不存在的模型时，该轮以对应错误码结束，不自动换模型。
8. 版本不在已验证表里时，第一次使用前在本机自动跑一遍「执行前不执行」硬前提验证：通过就放行并记入本机已验证，不通过就阻断；验证进行中与未通过的状态在运行时详情 / 诊断页标出，**状态栏不显示**；已知不兼容的组合按 FR17 阻断（产品负责人 2026-11-10 定，T06 方案 P2 选 c）。

## 注意

- 成员会话必须与用户全局配置隔离（需求 8.4、M1 技术设计 9.5）：用户自己的 hook、权限模式、未导入的 MCP / 技能 / 插件、全局 CLAUDE.md 都不进入会话。已实测采用“参数屏蔽”（`t0-findings.md` 2.2a）：`--setting-sources`（排除 user、project、local）、`--strict-mcp-config` + `--mcp-config`、`--settings`、`--plugin-dir`。内置技能照常加载；仓库内项目级设置一律不加载（需求 8.4，v1.63），按 O1 第 ③ 项实测确认。
- 不修改 CLI，不读写其凭据目录。
- 6.2 的 claude-agent-acp 不用于 M1，不要引入。
