## 目标

M1：用户看得到本机给 Claude Code 配了哪些 MCP、技能与插件；不能导入。成员会话里没有用户自己的 MCP 与用户级技能。

## 范围

**做（A）**

1. **只到名字这一层的发现**：MCP 的名字、连接方式、要填值的键名；技能的目录名；插件的键、它带的技能目录名、它自带 MCP 的名字与键名。不读 MCP 的命令、参数、地址和任何值，不打开技能目录里的文件。MCP 的名字、键名、技能目录名、插件键照原样显示，不过滤（产品负责人 2026-11-12 定，方案 PD-A1；需求附录 B 与第 9 章）；连接方式只显示固定的标签。
2. **导入列表与原因**：设置 › 运行时 的「从本机导入」入口列出上面这些，每一项标「还没启用」；导入命令一律拒绝并逐项给原因。不弹首次导入框、不显示红点。
3. **协议加法**：条目的「要填值的键」「为什么导不了」两个字段，一个错误码，视图跟上。
4. **两个开关**（默认关）：MCP 导入、技能导入各一个。M1 里它们只决定原因文字。

**不做（M1）**：导入 MCP 与技能、系统钥匙串、填密钥、开会话时把导入的 MCP 与技能交给运行时、移除、首次导入弹窗；插件导入。

## 验收标准

1. **能列出**：设置入口打开的列表里有本机的 MCP（名字、连接方式、键名）、技能（目录名）、插件，名字照原样，每一项标着「还没启用」的原因。
2. **不能导入**：导入命令被拒，逐项给出原因；不产生事件，数据目录的 `imports/` 下没有任何东西。
3. **不读敏感内容**：MCP 配置里 `env`、`headers` 的值、命令、参数、地址，技能目录里的文件内容，都没被读、没发给客户端（方案 RA1、RA2 的测试：断言读文件的调用记录与发给客户端的字节）。原文能出去的只有照原样显示的那四种名字；连接方式的原文、路径、解析器看到的值出不去，名字不进条目 id、错误与日志（方案 RA6）。
4. 成员会话的 `system/init` 里没有用户自己的 MCP 与用户级技能：由 T06 的隔离验收保证，本卡不重复验。
