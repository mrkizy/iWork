# T01 工作区骨架、协议、领域模型

- **风险**：高（地基，后面所有卡都依赖它）→ 先出方案 `docs/plans/T01.md`
- **依赖**：无
- **依据**：M1 技术设计第 2 节（进程与 crate）、3.3–3.4（帧与消息）、5.3（表，用于推出领域实体）、6.4（回合状态）、10.4（错误）；需求第 12 章（状态机）

## 目标

建好 Cargo 工作区与前端工程的骨架，定下协议与领域模型，让 T02–T08 可以各自并行开工而不互相等接口。

## 范围

**做**

1. Cargo 工作区，13 个 crate 按 M1 技术设计第 2 节命名与分层；`iwork-daemon`、`iwork-bridge-claude` 为二进制，其余为库。另建 `iwork-claude-hook`（hook 小程序，二进制，T06 填实现）、`iwork-bench`（T11 填实现）与 `iwork-fake-agent`（假运行时，二进制，T05 填实现）三个空 crate。
2. `iwork-proto`：
   - 帧类型 `Hello`、`Welcome`、`Request`、`Response`、`Event`、`Chunk`；
   - M1 全部命令、查询、事件的消息定义（命令表见下）；
   - 错误 `{code, message, retryable, details}` 与错误码枚举；
   - `ViewPatch`；
   - Rust 侧 prost 生成，TypeScript 侧 protobuf-es 生成，构建时生成、不入库。
3. `iwork-domain`：ID 类型（建议 ULID，方案里定）、实体与值对象、领域事件、状态机：
   - 回合：`queued → running → (waiting_approval ↔ running) → completed | cancelled | failed | interrupted`（另有 `cancelling` 过渡态，见需求第 12 章“取消先进入 cancelling”）；
   - 审批：`pending → approved | denied | voided`（不超时；voided 的触发条件见需求第 12 章，hook 超时防护引起的中断不作废）；从手动切到自动时边界内待审批转 `approved`，原因记为“模式切换自动放行”；
   - 对话、消息状态；项目路径状态（正常 / 找不到路径）。
4. `iwork-ports`：AgentPort、VcsProvider、StoragePort、ArtifactStore、ExecutionBackend、SecretStore、Notifier、Clock 等 trait 的签名（实现在后续卡）；异步接口用语言原生的 async trait，不引入 tokio。
5. `scripts/check-deps.sh`：检查 crate 依赖方向（`domain`、`ports` 不得依赖任何框架与 I/O 库，包括 tokio；`core` 不得依赖 `store`、`vcs-git`、`agent-acp`、`ipc`、`host`；`bridge-claude` 只依赖 `proto`；只有 `daemon` 依赖全部实现）。配 `deny.toml`。
6. `client/`：Tauri v2 + SolidJS + TypeScript（pnpm）空壳，能启动出一个空窗口，接入生成的 TS 类型。
7. CI：macOS、Linux、Windows 三平台跑 fmt、clippy、test、deny、check-deps、前端 typecheck 与 test。

**M1 命令最小集**（方案可补充，须在方案里列全）：SendMessage、CancelTurn、CreateAssistant、UpdateAssistant、DeleteAssistant、CancelAll、DecideApproval、SetApprovalMode、SetConversationModel（模型与思考强度）、SetPlayfulUi（轻松元素开关）、MarkRead、AddProject、CreateProject、InitRepository、CloneRepository、SetProjectsRoot、RelocateProject、PinProject、RemoveProject、UploadAttachment、ConfirmCredentialAttachment、ExecuteUserAction、DismissUserAction、SwitchDmProject、ConfirmAgentsMdDraft、ResumeTurn / AbandonTurn（继续或放弃中断的回合，放弃时其待审批转为已作废）、RevokeRule（撤销记住的规则）、ImportLocalConfig（按勾选导入本机 MCP / 技能 / 插件）、SetMcpSecret（填写 MCP 密钥，存入系统钥匙串）、StopUserAction（停止正在执行的亲手执行卡片）、DeleteConversation（删除项目对话，技术设计 9.0）、AddSecurityListEntry / RemoveSecurityListEntry（安全清单，技术设计 7.2c）。查询：GetConversation、ListConversations、ListProjects、ListAssistants、ListPendingItems（“待你处理”：待审批与其他待处理卡片）、GetQuota、GetRuntimeStatus、ListModels（按运行时返回可选模型与思考强度）、ListRules（记住的规则与项目规则）、ListLocalConfig（本机可导入的 MCP / 技能 / 插件）、ListSecurityLists。订阅：Subscribe / Unsubscribe。

**不做**：任何 I/O 实现、存储、网络、界面内容。

## 交付物

- 可编译的工作区与前端空壳；`AGENTS.md` “技术栈与常用命令”一节按实际命令更新。
- `proto/*.proto`，每个文件头注明兼容规则：字段只增不改号。
- 状态机实现与属性测试。
- CI 配置。

## 验收标准

1. 三平台 CI 全绿：`cargo fmt --all --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace`、`cargo deny check`、`scripts/check-deps.sh`、`pnpm -C client typecheck`。
2. `check-deps.sh` 有自测：用一个临时加入的违规依赖（测试夹具）跑它，必须失败。
3. 回合与审批状态机有 proptest：随机事件序列下不出现表外转换；终态之后不再转换；`denied` 永不变为 `approved`。
4. Protobuf 兼容测试骨架：用旧版本消息样本解码新版本类型通过（样本存 `proto/compat/`）。
5. `pnpm -C client tauri dev` 能起出空窗口（本地手动验证，报告里附截图）。

## 注意

- 所有对外字段英文命名；proto 包名带主版本（如 `iwork.v1`）。
- `iwork-domain` 里不出现厂商名、git 字样（VCS 用抽象的“基线版本”“工作区”）。
