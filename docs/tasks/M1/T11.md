# T11 基准与故障测试进 CI

- **风险**：中
- **依赖**：T10（基准框架与假运行时驱动可在 T05 完成后先搭）
- **依据**：M1 技术设计 10.1、10.2；需求第 14 章（阈值）

## 目标

把 M1 的 daemon 相关性能指标与故障测试变成 CI 里的自动化项；超阈值记为回归并在审查中标出，不阻止合入。

## 范围

**做**

1. `iwork-bench`：用假运行时驱动下列基准，输出 JSON 结果并与阈值比对：

| 基准 | 场景 | 阈值（需求第 14 章） |
| --- | --- | --- |
| 流式输出延迟 | 4 / 16 个假成员各 100 片段/秒；后台收到 → 客户端 Rust 侧收到 | P95 ≤ 100ms / ≤ 250ms（M1 量到 Rust 侧，界面可见部分 M2 补） |
| 唤醒延迟 | 审批通过 → 成员恢复运行，不含假运行时耗时 | ≤ 1s / ≤ 2s |
| 启动与恢复 | daemon 冷启动；客户端重连并补发 1 万条事件 | 冷启动 ≤ 1s；重开 ≤ 1s 恢复 |
| 写入 | 组提交下每秒命令数、单命令延迟 | 记录 P95（无硬阈值，进趋势） |
| 内存 | daemon 空闲 / 运行中 / 16 成员；单个桥接进程 | ≤ 80MB / ≤ 200MB / ≤ 400MB；≤ 60MB |
| 长时运行 | 4 成员连续 8 小时（夜间任务） | 内存增长 ≤ 10%，不崩溃、不丢事件 |
| 空闲 CPU | 无成员运行 10 分钟 | daemon 平均 < 1% |
| hook 开销 | `iwork-claude-hook` 冷启动 | 记录（无硬阈值） |

2. 故障测试矩阵（10.2）：在写入、推送、审批等待、取消的任意点杀掉桥接或后台服务，重启后验证：无重复执行、无丢失事件、待审批仍在、回合正确标为中断。
3. 协议兼容：旧版客户端 × 新版后台服务握手与字段兼容（用 `proto/compat/` 样本）。
4. CI 编排：短基准每次提交跑；8 小时长测每晚跑；结果存为构建产物并生成趋势；超阈值在 PR 上留评论标出。

**不做**：界面帧时与输入延迟基准（M2）。

## 验收标准

1. 全部基准在 CI 上可运行并产出 JSON 与对比结果；故意注入一个变慢的改动（测试分支），PR 上出现回归标注。
2. 故障矩阵每个注入点都有用例且通过。
3. 夜间长测至少成功跑完一次，报告附结果。
4. 所有阈值均达到，或在报告中逐项记录偏差与原因，交产品负责人决定是否调整阈值（调整须写入需求文档修订记录）。
