# T08 版本控制（git）与项目身份

- **风险**：中
- **依赖**：T01
- **依据**：M1 技术设计第 8 节、9.3；需求 FR19、AC34

## 目标

实现 `iwork-vcs-git`（VcsProvider 的 git 实现，M1 加粗的方法）与项目身份规则：一仓库一项目，去重、重新定位可靠。

## 范围

**做**

1. `detect(path)`：gix；返回仓库根、共享目录（common dir）；链接的工作树归到同一仓库。
2. `init(path)`：本机 `git init` + `git add -A` + `git commit`（沿用用户的 git 配置；用户未配置提交身份时给出可读错误；空目录用 `--allow-empty` 做首次提交）。
2a. 新建项目所需的目录创建：父目录不存在则创建；目标已存在且非空时拒绝。默认父目录 `~/iWork/projects/`（Windows `%USERPROFILE%\iWork\projects\`），可配置。
3. `clone(url, dest)`：`git clone --progress`，解析进度为事件；失败保留错误输出、可重试；不接触凭据（用用户自己的凭据助手）。
4. `baseline()`、`status()`、`diff(range)`：gix。
5. 能力声明：如“支持廉价隔离工作区”，M1 只声明不实现。
6. 项目身份：首次添加写 `.iwork/project.toml`（项目 UUID）；去重按共享目录的真实路径（解析符号链接、大小写规范化）；重新定位按 UUID 一致才关联；路径状态“找不到路径”。
7. 排序与置顶所需字段（`last_active_at`、`pinned`）的维护。

**不做**：worktree、提交、合入、受保护线监控（M2）；添加项目的界面流程（T10）。

## 验收标准

1. 临时仓库夹具测试：普通仓库、子目录、链接工作树、裸仓库、子模块，`detect` 结果正确；子目录添加时归到仓库根。
2. 同一仓库经符号链接路径、大小写不同路径、链接工作树分别添加，都识别为已有项目。
3. 移动仓库目录后标为“找不到路径”；选择新位置：UUID 一致则重新关联，不一致则拒绝并说明。
4. 非 git 目录：`detect` 返回“未受版本控制”；`init` 后可添加且有首次提交。
4a. 新建项目：空目录 `init` 后有一个空的首次提交；目标目录已存在且非空时拒绝；默认父目录不存在时自动创建。
5. `clone` 进度事件单调递增；无效地址与中途断网都给出错误并可重试（用本地 `file://` 仓库和一个故意失败的地址测试）。
6. `iwork-core` 不依赖 `iwork-vcs-git`（`check-deps.sh` 保证），核心逻辑里没有针对 git 的分支（审查项）。
