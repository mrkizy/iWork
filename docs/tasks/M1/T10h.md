# T10h 补丁卡片（亲手执行的文件补丁）

> 从 T10e 拆出（产品负责人 2026-11-12，需求附录 B）。T10e 的方案审了三轮，15 条 finding 里有 5 条只和补丁有关，所以单独成卡；仍在 M1 内做，AC36 不改。本卡由 architect 起草，范围和验收是新写的，没有照搬的原文。

- **风险**：高（以用户身份改写系统底线范围内的文件；先出方案 `docs/plans/T10h.md`，审过再实施）
- **依赖**：T07、T10a、T10e（卡片宿主、执行后端的端口、用户通道都由 T10e 交付）
- **依据**：M1 技术设计 7.2a 第 1、4 条；需求第 9 章（系统底线、亲手执行）、AC36；AGENTS.md「安全不变量」（亲手执行卡片）；T07 方案 5.4、Q6；T10e 方案第 0a 节（卡片宿主义务表）与第 14 节（三轮审查里补丁的五条）

## 目标

Agent 用 Edit 改系统底线范围内的文件被拒时，用户能在卡片上看到精确的新旧内容，点「执行」，由 iWork 以用户身份把这一处修改写进去。

## 范围

**做**

1. **恢复 Edit 的卡片判定**：T10e 为了先不做补丁，把 T07 的 `propose_user_action` 改成 Edit 不出卡片（只拒绝、提示改用一条命令）。本卡改回来，Edit 命中底线重新产出 `Proposal::Patch`。
2. **补丁的执行后端**：`ExecutionBackend` 加补丁的两段（可以丢弃的准备、只做落位的那一下）；`iwork-host` 实现；写文件的步骤放在 `iwork-rootfs`，不在 host 里另写一套。
3. **接进 T10e 的卡片宿主**：补丁卡片的任务（准备 → 启动边界 → 落位）和它产出的事实；对照 T10e 的义务表逐行说明补丁卡片怎么走，补丁特有的义务加行。
4. **落位之后的说明**：清理没做完时（临时名没删掉、目录没落盘）给用户看的一段话，作为这张卡片的输出。
5. **已知限制**：补丁写文件守不住的边界，写成一条交产品负责人登记进需求第 9 章。

**不做**

- 整文件 Write 出卡片（T07 Q6 已定只拒绝，不变）。
- Edit 带 `replace_all` 的多处替换（卡片上只有一组新旧文字，多处命中按冲突处理）。
- 改卡片哈希的编码（T10e 方案 Q6，另行决定）。
- 卡片宿主的机制本身（T10e）。本卡只往里加一种卡片。

- 代码：`iwork-core`（Edit 的卡片判定）、`iwork-ports`（端口的补丁两段）、`iwork-rootfs` 与 `iwork-host`（写文件）、`iwork-daemon`（卡片宿主里的补丁任务）。

## 验收标准

1. **AC36 的补丁部分**（端到端）：Agent 用 Edit 改凭据目录替身下的文件 → 被拒并出补丁卡片，卡片上是精确的新旧文字与理由；用户点「执行」后文件是新内容，审计记为用户；Agent 只得知是否执行与退出码；卡片不能记住；全开档也出现。
2. **不经链接、不写坏文件**：目标路径逐级不跟随链接；旧文字恰好出现一次才替换，零次或多次报冲突；任何一步失败，目标的内容和权限都不变。
3. **并发不丢内容**（T10e 审查 1/F-3）：两张补丁卡片几乎同时执行、改同一个文件的两处：两处修改都在，或者后一张明确报冲突；不允许两张都成功却丢了一张的内容。别的程序在打补丁的过程中改了文件：报冲突，外面的改动留着。守不住的那一个窗口（复查之后、落位之前）写进已知限制。
4. **临时文件不放宽权限**（1/F-4）：临时文件从创建起只有本人可读写，写入和失败清理期间都不放宽，最后才设最终权限；新建文件的默认权限在方案里写明。「写到一半暂停」「中途失败」各有测试。
5. **慢的、要排队的都在启动边界之前**（2/F-2）：等补丁锁、写临时文件、慢落盘、复查全程不碰目标，可以丢掉；边界之后只剩落位那一次系统调用。前一张持锁超过 1 秒、后一张在排队、落盘很慢，这时删除对话或封口：没有文件被改。封口到时还有卡在落位里的，返回剩余数，不当成清空。
6. **落位成功就是执行了**（2/F-3）：改名或硬链接成功之后，卡片是 `Done`；之后清理出错只写成给用户的说明，不回滚、不报成没执行。落位之前、落位之后各崩溃一次的演练：重启后卡片是结果未知，没有第二次落位，残留临时文件的权限不比目标宽。
7. **落位之后不挡事**（3/F-5）：落位一成功就放补丁锁；目录落盘、说明保存都有时限，卡住时不挡这张卡片的结局，也不挡后面排队的补丁。
8. **进了义务表**：方案对照 T10e 第 0a 节逐行写明补丁卡片的走法；受理函数被中止、存储忙、任务 panic 三种情形下，补丁卡片的结局各有测试，结论和命令卡片一致。
9. **回归**：命令卡片的全部验收（T10e）不受影响；整文件 Write 命中底线仍然只拒绝。
