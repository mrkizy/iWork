# T09 客户端：Rust 侧状态与帧合并、M1 界面

- **风险**：中
- **依赖**：T03、T04（界面开发可先对接假数据，T03 完成后接真连接）
- **依据**：M1 技术设计 3.6、3.7；`docs/design/ui-m1.md`、`docs/design/ui/*.png` 与 `docs/design/design-system/`（令牌、动效、助手形象 SVG）；需求 FR03、FR15、第 14 章
- **角色**：界面部分先由 architect 对照画布出实现说明（组件拆分、状态、交互细节），functional_reviewer 审过再实现

## 目标

客户端 Rust 侧做全部重活（连接、事件应用、视图增量计算、每 16ms 合并一次 `ViewPatch`），网页层只渲染；按画布实现 M1 全部页面，浅色与深色两套主题。

## 范围

**做**

1. `iwork-client-core`：持有连接与本地状态库（按 id 索引）；网页层声明可见视图，Rust 侧只为可见视图算增量；每 16ms 最多一次，由网页层经 invoke 长等待以原始字节取 `ViewPatch`（不用 Tauri `Channel` 推，产品负责人 2026-11-10 同意）；断线自动重连并按最后 `seq` 重订阅。
2. 用户操作经 Tauri `invoke` 交 Rust 侧转为命令（带 `command_id`）。
3. 网页层（SolidJS）：`ui-m1.md` 第 1 节列出的 M1 页面；第 2 节跨页面规则全部满足；设计令牌与动效直接引用 `design-system/tokens.css`、`motion.css`，助手形象用 `design-system/characters/*.svg`；长列表虚拟滚动（十万条历史）。
3a. 已作废的审批卡片置灰、按钮不可点，标注“已作废”及原因，并从“待你处理”计数中移除。
3b. “待你处理”页：列出全部待审批与待处理卡片（`ListPendingItems`），点击跳到对应对话位置。
3g. 删除对话（技术设计 9.0）：侧栏项目对话右键菜单“删除”，确认框写明“对话记录将删除，不影响代码文件”；助手私聊的右键菜单不含删除。
3h. 对话标题（技术设计 9.0a）：项目对话发出首条消息前显示“新对话”，之后显示首条消息前 20 字；右键“重命名”就地编辑，回车确认、Esc 取消，空标题不能提交；改过的标题不再自动变化；助手私聊与成员子对话没有重命名。
3c. 助手管理界面：侧栏“助手”分区的“+”新建；助手主页“配置”页可编辑名字、头像、提示词、运行时、工具开关，修改即时自动保存；侧栏右键助手弹出菜单（打开对话 / 配置 / 删除，iWork 无删除），删除前确认框写明不可撤销与私聊工作目录路径；设置里的“记住的规则”页（`ui-m1.md` 第 2 节第 15 条）。界面见画布第 13 页（`ui/13-*.png`）。
3d. 亲手执行卡片（`ui-m1.md` 第 2 节规则 12）：显示命令或补丁 diff、理由、“执行”“复制命令”“忽略”三个按钮；无记住选项；执行后显示退出码与输出。后台服务崩溃后的「结果未知」状态：显示「执行结果未知，请自行核对」、命令与已收到的输出，带「我已核对」按钮（发 `ConfirmUserActionEnded`，技术设计 7.2a）；删除对话停在「删除中」时提示「有一张卡片的执行结果无法核对，请确认后继续删除」。凭据附件的确认提示。
3e. 运行时与模型菜单（画布第 1、13 页，`ui/01-Main-modelmenu.png`）：输入框按钮显示“运行时 · 模型”；菜单分运行时、模型（仅本对话）、思考强度三节，可手填模型 ID；对话开始后运行时一节置灰；助手配置页与新建助手弹窗的运行时 / 模型 / 思考强度三个下拉。
3f. 轻松元素（需求 FR22，技术设计 9.7）：“搞定”印章按改动摘要事件上的 `celebrate` 显示；设置里的“轻松元素”开关；安全相关卡片上不出现轻松元素。**不做**经验条、成就卡、小队小结：画布侧栏的“LV 7”与成就卡只作远期参考，M1 侧栏不渲染。
3h. 设置 › 安全清单（`ui-m1.md` 第 2 节第 16 条）：界面待产品负责人定，定之前不实现。
4. 系统通知：待审批时发系统通知；点击通知打开对应对话。
5. 附件入口的客户端部分：拖入、粘贴、选择；20MB 检查；本机文件只传路径，粘贴数据用 `Chunk`。
6. “完全退出 iWork”菜单、“正在切换版本”提示、后台服务连不上时的诊断页。

**不做**：M2 页面（团队执行、审查、台账、团队与协作方式）；界面帧时基准（M2）。

## 验收标准

1. `ViewPatch` 合并单元测试：同一帧内对同一对象的多次修改合并为一次；不可见视图不产生增量；帧间隔不小于 16ms。
2. 断线重连：模拟后台服务重启，界面状态与重启前一致，无重复消息（集成测试）。
3. 打包产物中搜索不到“主管”二字（`grep` 检查进 CI）。
4. 未读数规则：只有“发给用户的消息”与“待处理卡片”计数，打开对话清零（组件测试 + Rust 侧单元测试）。
5. 额度取不到时显示“—”；悬停显示窗口类型与重置时间（组件测试）。
6. 超过 20MB 的附件当场提示且不发送（组件测试）。
7. 十万条消息的对话中滚动不卡顿：报告里给出本机测得的切换对话耗时与滚动帧时（M1 只记录，不设门槛）。
7b. 轻松元素开关关闭后：不盖章、头像不浮动、无“嗨”气泡、眼睛不跟随，表情仍随状态变化；审批、亲手执行卡片上从不出现印章。
7a. 头像互动：悬停、戳一下、连戳 3 次生气、侧栏眼睛跟随鼠标均按 `ui-m1.md` 3.3 实现；开启“减少动态效果”后全部停用；侧栏 20 个助手时鼠标持续移动，帧时仍满足第 14 章阈值（报告附测量）。
8. functional_reviewer 对照 `ui/*.png` 与画布逐页验收，浅色与深色各一遍，附截图。
