# T05 AgentPort、ACP 客户端、假运行时、进程监管

- **风险**：中
- **依赖**：T01
- **依据**：M1 技术设计 6.1、6.4、6.5、第 10 节开头（假运行时）；`docs/design/t0-findings.md` 第 5 节

## 目标

实现 `iwork-agent-acp`：后台服务只通过它和任何运行时说 ACP；做一个可编排的假运行时，让所有回合、审批、取消、崩溃场景不依赖厂商就能自动测试。

## 范围

**做**

1. AgentPort 的 ACP 实现（官方 `agent-client-protocol` crate）：初始化与能力协商、开会话（工作目录、模型、提示词、MCP、可恢复的旧会话 id）、prompt、cancel、权限回调 `on_permission`。MCP 的透传移到 T10：端口里的 `McpServerRef` 只有 id 和名字，拼不出启动配置，要等本机导入接入 SecretStore 后一起做；本卡在 `spec.mcp` 非空时返回可读错误（supervisor 2026-11-09 裁定）。
2. 厂商原始事件在本层标准化为领域事件；原始事件只用于诊断，脱敏、限量。
3. 运行时登记：记录 CLI 路径、CLI 版本、适配器版本、协议版本（t0-findings 5.2）；已知不兼容组合阻止运行（FR17）。
4. 进程监管：每个桥接独立进程组（macOS / Linux `killpg`；Windows Job Object）；取消超过 3s 未结束即结束进程树；每 2s 采样内存与 CPU。
5. **假运行时** `iwork-fake-agent`（二进制，说 ACP agent 端）：按脚本（YAML/JSON）产生文字片段、工具调用、权限请求、延迟、崩溃、挂起；可设输出速率（如 100 片段/秒）。脚本格式写进文档。
6. 回合编排的最小闭环：SendMessage → 开会话 / 续接 → prompt → 流式事件入库与推送 → 结束。

**不做**：Claude Code 适配器（T06）；审批判定逻辑（T07，本卡用一个“全部放行 / 全部拒绝”可切换的桩）。

## 验收标准

1. 假运行时跑通完整回合：文字流、工具活动、权限请求（放行与拒绝两种）、结束，事件序列与预期快照一致。
2. 取消：回合运行中取消，3s 内进程树全部结束，无孤儿进程（测试结束后按进程组 / Job 检查）。
3. 假运行时中途崩溃：回合标为 `failed` 或 `interrupted`（规则在实现报告里说明），后台服务不受影响。
4. 权限请求在桩返回前一直挂起（测试等待 ≥ 60s 不超时）。
5. 不兼容的版本组合被阻止运行，并给出可读错误。
