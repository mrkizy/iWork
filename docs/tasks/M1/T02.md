# T02 事件存储、投影、制品存储、迁移

- **风险**：高（数据不可丢）→ 先出方案 `docs/plans/T02.md`
- **依赖**：T01
- **依据**：M1 技术设计第 5 节、3.5（持久事件与流式增量）、10.2（故障注入）；需求第 12 章（outbox、幂等、回放不重做外部动作）

## 目标

实现 `iwork-store`：一个 SQLite 库同时存事件日志与投影，一次命令一个事务，崩溃不丢已确认事件；大文件进按内容寻址的制品存储。

## 范围

**做**

1. 数据目录定位（三平台，见 5.1）与目录结构。
2. 表：M1 技术设计 5.3 全部表与索引。审批模式设置（项目默认、对话级、成员单独设置）的存放方式在方案里定，必须经事件写入。
3. 单写者线程 + 只读连接池；WAL；`synchronous=FULL`；组提交（2ms 窗口）。
4. 命令事务：追加事件 + 更新投影 + 写 outbox + 记录 `command_id`；重发同一 `command_id` 返回上次结果。
5. 流式增量的检查点：运行中每 500ms 写一次消息内容检查点；消息结束写完整内容。
6. 投影重建：从事件重放生成投影，重放不触发 outbox 投递。
7. 制品存储：`artifacts/sha256/<前2位>/<其余>`，临时文件 → 校验 → 原子改名；引用计数；回收无引用对象。附件区 `attachments/sha256/…` 用同一套实现、独立目录（技术设计 5.4，需求 v1.68）。
8. 迁移：编译进二进制、只向前；执行前 `VACUUM INTO` 备份；失败保持旧库、拒绝启动。

**不做**：事件推送给客户端（T03）、多成员与审查相关表。

## 交付物

`iwork-store` 实现 StoragePort 与 ArtifactStore；测试；写入基准的初版（供 T11 收编）。

## 验收标准

1. **崩溃注入**：子进程循环提交命令，父进程在随机时刻 `kill -9`，重复 ≥ 200 次；每次重启后：所有已返回“已提交”的命令都在，没有半个事务，`seq` 连续无洞。
2. 重发同一 `command_id` 返回相同结果，事件不重复（proptest）。
3. 投影重建结果与在线投影逐表一致；重建期间 outbox 无新投递。
4. 制品：相同内容只存一份；写入中途崩溃不留下以哈希命名的坏文件；回收不误删有引用的对象。
5. 迁移：注入一个失败的迁移，旧库保持可用且备份存在；正常迁移后数据一致。
6. 写入基准：组提交下单命令延迟 P95 与每秒命令数有输出（数值记入报告，阈值由 T11 判定）。

## 注意

- 事件载荷是带版本的 Protobuf，只追加不修改。
- 日志不得写入消息正文与附件内容（只写 id 与长度）。
