## 目标

把 T04、T06、T07、T08、T09 接成一条真的链路：打开项目就能和 iWork 对话，所有越权动作都走审批，关窗后工作继续。其余六张 T10 小卡都在这条链路上做。

## 范围

**做**

1. **后台组装**（拆卡时补，来自 T07、T04 方案的交接）：把真实审批引擎（T07）、Claude 适配器（T06）、版本控制（T08）接进 daemon。提交观察者用 T04 的 `set_commit_observer`：写线程上只做非阻塞唤醒，由独立异步任务跑 `sync()`，限时 5 秒（T07 方案 6.10 接线契约）。引擎读到不认识的事件种类时原样上传 `UnknownKind`，启动按退出码 12 处理（T04 方案 2.2 第 178 行、交接第 1414 行；PD6）。
2. **端到端**（原范围 5）：和 iWork 的项目对话（流式、工具活动、审批卡片、取消单个 / 全部）；「待你处理」列表。M1 不做计划卡片。续接失败用摘要新开（需求 v1.78）在编排核心里已做完（T06 方案 5.2a、S2b），本卡只做两件：组装回合端口时把真实的读模型交给 `history`；受理 `SendMessage` 时用户消息与 `TurnQueued` 必须在同一次提交里写入（`summary_source` 靠它把这一轮的请求挡在摘要外，形状不对时查询报错，T06 方案 5.2a、S2b 审查 2/F-3），端到端用例覆盖一次「续接失败 → 摘要新开」确认没有报错；点「继续」组装续接回合的 `TurnPlan` 时，用和新回合**同一个**「用户消息 → blocks」函数把这一轮的请求转好填进 `request`（`Ready`），转不出来（制品读不到、附件没了）填 `Unavailable(原因)`，不另写一条转换路（T06 方案 5.2a，S2b 审查 1/F-3）。诊断里列出带 `replaced` 的 `TurnSessionBound`（查询归本卡，显示归 T09；同一回合后面还有一条不带 `replaced` 的绑定、记回旧编号的，是那次恢复被退回了，要按这个认出来）。
3. **T09 交接**（T09 方案第 3 节）：G2–G6 的填值与读模型查询；G3 的 convert 改动，配对拍 `approval_proto_roundtrip_all_states`；G4 `last_turn_state`；G5 回合、工具调用、审批决定、卡片状态事件带 `conversation_id`，设置范围加 `rule` 流；G6 侧栏的流式增量路由（只把路由键改成 `conversation:<id>` 解决不了，见 T09 方案）。G10 消息锚点的后台查询 `ListAnchors`、G11 `GetConversation` 的 `after_message_id`、`around_seq` 与行级游标 `before_seq`、`after_seq`（T09 组 2b 审查 5/F-3，2026-11-12 加）几种取页方式（T09 方案 2.9，假后台已有参照实现）。「回合结束行」按行计数时和客户端同一条件：已结束、不在跑、不是中断的回合才算一行（中断的回合不出结束行），否则真后台和客户端按行数取的页对不上（T09 步 5c 实现时核出，2026-11-12）。另：`GetConversation` 带出 `Turn.project_content`（T06 方案 3.1c：仓库内容送进会话的结果与撤回原因，S6-6 提交回合流事件 `ProjectContentReported`，本卡做投影、查询和订阅接线：投影只在收到这个事件时换值，收到 `TurnSessionBound` 等别的事件不清这个字段；2026-11-12 加）。
4. **系统通知**（T09 方案 2.8、第 3 节 D6、第 14 节；产品负责人 2026-11-11 改定）：全部由后台发，客户端不发。`iwork-host` 实现 `Notifier`（申请通知权限，拿不到就只记日志；Linux 只记日志）与「把桌面客户端叫到前台」；端口的 `SystemNotification.open` 加条目 id。待处理新增一项时按规则决定发不发（纯函数）：桌面客户端报了窗口在前台，并且正看着这一项的对话或「待你处理」页 → 不发；同一项只发一次；已处理或作废的不发。受理 `ReportPresence`（连接级，不产生事件，连接关闭即清）与 `GetOpenTarget`；用户点通知后记下目标（只记确实点过的那一项）。macOS 上 M1 的提醒实际靠客户端的 Dock 角标与跳动（T09）；没有 Developer ID 签名的构建拿不到通知权限，这里的代码在有签名的构建上才真正弹出来。
5. **录像对拍**（T09 方案第 11 节步 11）：用真后台加假运行时重录场景，与假后台的录像对拍终态。
6. **删除对话时删运行时的会话记录**（需求 FR18 v1.78；技术设计 9.0 第 4 步；T06 方案 5.5）：先取齐这条对话各回合的会话编号（从全部 `TurnSessionBound` 事件里取，含 `runtime_session_id` 与 `replaced` 里的旧编号；不能只取回合投影上的最后一个值：续接失败恢复没成功时会补记一条旧编号，被退回的新编号只在事件里，T06 S2b 审查第 3 轮）；会话线先 `retire()`；再删 iWork 自己的记录；最后调 `AgentPort::forget_sessions`。`Refused` / `Failed` 各写一条审计，删除命令照常成功，不重试。

**不做**：助手管理与私聊（T10b）、添加项目的界面流程（T10c，本卡测试里的项目用夹具登记）、附件（T10d）、亲手执行与安全清单（T10e）、本机导入（T10f）、模型与额度（T10g）。

## 验收标准

（端到端测试用假运行时；另用真实 Claude Code 跑一遍冒烟，报告附记录）

1. 审批端到端（原验收 7，手动档）：工作区外写入、git push、删除都出审批卡片，「待你处理」计数加一（macOS 上客户端的 Dock 角标与跳动由 T09 验收，这里只断言计数），并按规则调用 `Notifier`（用假 `Notifier` 断言：没有桌面客户端连着时调用；窗口在前台正看这个对话或「待你处理」页时不调用；看着别的对话时调用；同一项重连、重启后不重复；已决定的不调用。真 `Notifier` 拿不到权限时只记一行日志、不报错。系统通知真的弹出来、点通知跳到对应项，要在有 Developer ID 签名的构建上验证，M1 不作为本卡的通过条件）；联网不出审批卡片；全开档下只有 git push 出卡片；拒绝后不执行，且在本对话内、直到用户发出下一条消息之前不能绕过（AC05）；客户端关闭期间的待审批，重开后仍在。
2. 关窗后回合继续运行并完成，重开后看到完整结果（原验收 8）。
3. 接线（T07 方案 1765）：`engine_sync_wiring_real_observer` 用真实存储加真实观察者通过。**这是本卡的合入门槛**，不能再往后推。
4. 未知事件种类（T04 方案 S8、PD6）：真引擎读到不认识的事件种类时，后台以 12 退出，数据不被改动。
5. 录像对拍：全部相等，或每条差异都有说明。
6. 续接失败（需求 v1.78）：用假运行时让续接回「会话记录不存在」，回合照常完成，界面没有任何提示，审计里有原因与新旧会话编号；`summary_source` 用真实存储取到的是这条会话线的消息，这一轮的请求认得对。
7. 删除对话：`forget_sessions` 收到的编号恰好是这条对话的（含被换下来的旧编号），在会话线 `retire()` 之后调用；假适配器回 `Failed` 时删除命令仍成功、审计里有一条。
