# T10 M1 功能：助手私聊、附件、添加项目、本机额度

- **风险**：中
- **依赖**：T06、T07、T08、T09
- **依据**：M1 技术设计第 9 节、6.4；需求 FR03、FR15、FR19、AC21、AC33、AC34；`docs/design/ui-m1.md`

## 目标

把前面各卡组合成 M1 的四项用户功能，并完成 M1 的端到端闭环：打开项目即可与 iWork 对话，所有越权动作经审批，关窗后工作继续。

## 范围

**做**

0. **助手管理（最小）**（9.1a）：新建、编辑（名字、头像、提示词、运行时、工具开关；子代理始终可用，不提供开关）、删除（9.1a，不提供停用）；iWork 不可删除，可重置为内置默认配置（`ResetAssistant`，需求 AC21）。
1. **助手私聊**（9.1、6.4）：每个助手一条 `assistant_dm` 对话；项目选择器列出全部项目 + “私聊”（M1 没有团队）；每条消息记 `context_project_id`，切换生成“切换到 X”分隔事件；底层按“助手 × 项目”各一条 CLI 会话线，切换项目时工作目录、AGENTS.md、审批规则随之切换，其他项目段内容不带入；“私聊”的工作目录为 `~/iWork/assistants/<助手名>/`（不在数据目录内，见 M1 技术设计 9.1），任何仓库都算工作区外。内置助手 iWork 存在且不可删除（AC21）。
2. **附件**（9.2）：后台服务再查 20MB；计算 sha256；仓库内文件只记路径引用，其余复制进附件区 `attachments/`；图片 → ACP image 块（运行时不支持时提示），其他 → resource_link（指向只读区中的副本）；凭据目录内的文件返回“需确认”，确认后内容嵌入消息、副本存 `private/`，私钥拒绝（9.2 第 3a 条）。
2a. **亲手执行**（7.2a）：`iwork-host` 的用户执行（ExecutionBackend）；`ExecuteUserAction` / `DismissUserAction` / `StopUserAction` / `ConfirmUserActionEnded` 的受理与审计（崩溃后「结果未知」的收尾按技术设计 7.2a 做法 A，演练在 T04 验收 3）。MCP 密钥经 `iwork-host` 的 SecretStore 存入系统钥匙串（4a）。
2c. **安全清单**（技术设计 7.2c）：`AddSecurityListEntry` / `RemoveSecurityListEntry` / `ListSecurityLists` 的受理、持久化与审计，清单变化在新启动的会话中生效（写入沙箱配置与审批规则）；按 AC41 经命令端到端验收，不依赖界面（界面待定）。
2b. **模型与思考强度**（9.6）：助手默认值、对话覆盖、每轮记录、对话内的切换记录；端到端验收 AC37。
3. **添加项目**（9.3）：入口三种，方式三种（打开文件夹、克隆、新建项目）；新建与克隆默认放 `~/iWork/projects/`，设置里可改；`detect` → 已知则跳转、未受版本控制则提示并可一键初始化；克隆进度；AGENTS.md 草稿由 iWork 跑只读回合产出，以卡片展示，用户确认后由后台服务写文件；写 `.iwork/project.toml`、登记、进入新对话；移除项目不改动仓库内容。
4a. **本机导入**（9.5、FR20）：Claude Code 首次接入时发现并列出本机 MCP、技能、插件（只取技能与 MCP），提示一次；勾选导入；MCP 密钥重新填写存系统钥匙串；设置 › 运行时 提供再次导入入口，不弹窗、不显示红点。开会话时把导入的 MCP 经 ACP `session/new` 的 `mcpServers` 透传给运行时（T05 移交）：需要给端口的 `McpServerRef` 补启动配置（stdio 的命令、参数、环境变量名；http 的地址、请求头名，只加字段），密钥值不进端口，由适配器从 SecretStore 取。
4. **本机额度**（9.4）：Claude Code 的 `rate_limit_event` 写入 `quota_snapshots`，上报了哪些窗口显示哪些，空闲时显示最近值与观测时间；Codex、agy 显示“—”；“本对话用量”来自每回合用量。
5. 端到端：与 iWork 的项目对话（流式、工具活动、审批卡片、取消单个 / 全部）；“待你处理”列表。M1 不做计划卡片。

**不做**：多成员、转交 iWork 的跨助手协作（M2）、记忆写入。

## 验收标准

（端到端测试用假运行时；另以真实 Claude Code 跑一遍冒烟，报告附记录）

1. 新建项目后无需任何配置即可与 iWork 对话（AC21）。
1a. 助手管理：新建的助手出现在侧栏并有私聊目录；禁用某个工具后，该助手会话中该工具不出现，强行调用被拒绝；删除后按 AC40 验收；iWork 无法删除。
2. 助手私聊：切换项目后新回合的工作目录与审批规则是新项目的；其他项目段的内容不出现在新会话的输入中；选“私聊”时写任何仓库都触发询问。
3. 附件（AC33）：拖入、粘贴、选择三种方式的图片与文件都送达运行时；仓库外文件可被 Read 与 `cat` 读取、不触发询问，写入被拒；导入技能里的脚本可被执行、不能被修改；附加的 `~/.npmrc` 不出现在只读区；运行时不支持图片时界面提示。附加 `~/.npmrc` 先提示、确认后送达；附加 `id_rsa` 与 `*.pem` 被拒绝（AC36）。
4. 添加项目（AC34）：本机文件夹、Git 克隆、拖入、新建项目四种方式；新建与克隆默认落在可配置的默认目录下；非 git 目录提示并可初始化；重复添加跳转到已有项目；移除后仓库内容不变（对比文件哈希）。
5. AGENTS.md 草稿：未确认前仓库里没有该文件；确认后由后台服务写入。
5a. 本机导入（AC35）：首次接入时提示一次，重启后不再提示；设置入口可再次导入；导入的 MCP 与技能出现在会话的 `system/init` 中，未导入的不出现；数据库与日志中检索不到 MCP 密钥明文。
6. 额度：有 `rate_limit_event` 时显示对应窗口；没有时显示“—”。
7. 审批端到端（手动档）：工作区外写入、git push、删除均出审批卡片并发系统通知，联网不出审批卡片；全开档下只有 git push 出卡片；拒绝后不执行，且在本对话内、直到用户发出下一条消息之前不可绕过（AC05）；客户端关闭期间的待审批在重开后仍在。
8. 关窗后回合继续运行并完成，重开后看到完整结果。
