# iWork M1 界面说明

界面原型是产品负责人的在线设计画布《iWork 产品形态原型》（15 张页面，含浅色与深色）。本目录 `ui/` 是画布的静态截图（1440×900，浅色；首页另有深色版；第 10 页有“展开菜单”与“已切到自动”两种状态），供实现时对照。截图与画布不一致时以画布为准，画布与需求文档不一致时以需求文档为准；截图里的数据都是示意。

设计系统素材（令牌 CSS、动效 CSS、助手形象 SVG、图标）已导出到 `design-system/`，实现时直接引用，用法见其中的 README。

## 2 跨页面规则（已确认，实现时不得改动）

1. 界面任何位置都不出现“主管”二字；对用户它叫 **iWork**，在助手列表里排第一并标“默认”。
2. 角色在界面上统称“助手”；侧栏有“助手”分区，每个助手有名字与头像（字头像），点进去默认是与它的对话。
3. 侧栏结构（2026-11-10 统一，全部 M1 画板同一版；画布第 1–5、8–11、13、14 页）：iWork 标志 → “+ 新对话” → “待你处理”（计数）→ 项目分区 → 助手分区 → 底部固定：项目设置入口（团队与协作方式 / 审查 / 设置与运行时；M1 只显示“设置与运行时”，见 2a 第 4 条）与本机额度一行。
   - **项目**：标题右侧图标按钮“+”添加项目。每个项目一行（展开箭头 + 项目名 + 未读数，未读数为该项目下全部对话之和），按最近活动排序，可置顶。当前项目默认展开，其余收起；点箭头可展开或收起任一项目，展开状态按项目记住。
   - **项目下的对话**：展开后列出最近 5 个对话（状态圆点 + 标题，缩进一级），末尾一行“全部对话”打开该项目的完整对话列表。对话有成员子对话时（如“架构 / 开发 / 审查”），在当前对话下再缩进一级列出。
   - **对话右键菜单**：打开 / 重命名 / 删除（删除见技术设计 9.0、T09 3g；重命名为就地编辑，见 9.0a、T09 3h）。见 `ui/01-Main-convmenu.png`。
   - **对话标题**：项目对话取首条消息前 20 字（超出加“…”），发出首条前显示“新对话”，不用 AI 生成；重命名后不再自动变化。助手私聊标题为助手名，成员子对话为角色名，都不能重命名。
   - **找不到路径的项目**：项目名划线，带“找不到路径”标签与“重新定位”（FR19，见画布第 9 页）。
   - **助手**：每个助手两行：头像 + 名字，下面一行是它最近一条动态（截断），右侧未读数。右键菜单：打开对话 / 配置 / 删除（iWork 无删除，见第 13 页）。
   - 侧栏数据来自“侧栏摘要”订阅（技术设计 3.5 节 Subscribe）：项目未读数、展开项目的最近对话、每个助手的最近动态与未读数。
4. **未读数**只统计“发给用户的消息”和“待处理卡片”（审批、计划确认等）；打开对话即清零。侧栏以数字徽标显示。
5. **本机额度**：侧栏底部一行，每个运行时一个“名称 + 细进度条 + 百分比”，悬停显示窗口类型与重置时间；取不到显示“—”。对话里另有“本对话用量”标签。
6. **附件**：拖入（整块对话区显示虚线框“松开以添加”）、粘贴、回形针图标按钮三种入口；输入框上方显示缩略图或文件卡片，可移除；单个不超过 20MB，超限当场提示。仓库外文件标注“仓库外文件”。
7. 按钮尽量用图标按钮（带 `aria-label` 与悬停提示），不堆文字；不出现“暂停团队”之类按钮（只有取消）。
8. 审批卡片：以 `10-ApprovalMode-*.png` 为准（`03-Board.png` 里“允许一次 / 本任务内允许”是旧版）。按钮为“允许”（主按钮）、“记住：仅这一次 ▾”（可选一次 / 本对话 / 本项目 / 永久）；“必问”动作（推送、发布、写会被自动执行的配置、删除、丢弃未提交改动）与清单外的沙箱外执行不显示记住选项，只有“允许”（一次）与“拒绝”；沙箱外执行卡片标明“将在沙箱外运行，命令带起的脚本也不受沙箱约束”；越界请求带“越界：…”标签，自动模式下 AI 审查未通过时显示理由；“执行脚本”类动作要标注审批看不到脚本内部（M1 技术设计 7.3）。
9. 审批档位切换（已确认，见第 10、11 页；需求 FR11 v1.46）：
   - 入口在输入框工具栏、附件按钮右侧：盾牌图标 + 档位名 + ▾；自动、全开时盾牌内带勾；全开时档位名用赭红粗体、按钮底色淡赭红，常驻醒目。
   - 点开为菜单：标题行写明生效范围（iWork 对话里“对本对话全体助手生效”，助手对话里“仅对 X 生效”）；三个选项各带一句说明（文案已由产品负责人定稿）：手动“写文件、执行命令前始终询问”；自动“仅对检测到的风险操作请求批准”；全开（标“仅本对话”）“可不受限地访问和操作一切，只有 git push 仍会询问”。说明只是概括，各档的实际行为以需求 FR11 为准。菜单里不放项目默认值与项目设置入口。
   - 切到全开每次弹确认框：说明哪些助手受影响、只有 git push 仍会问、“凭据和 iWork 数据仍受保护，只有需凭据的命令（如 git pull）会在沙箱外运行”、只在本对话有效（需求 v1.65）；已单独设置的助手单列“不受影响”。按钮“取消”“切到全开”（赭红）。
   - iWork 对话的菜单里列出已单独设置、不受本次切换影响的助手。
   - 单独设置：按钮上显示橙色“断开链接”图标（悬停提示“单独设置，不跟随 iWork”），不用文字标签；恢复跟随是菜单标题行右侧的“链接”图标按钮。跟随时两者都不显示。
   - 团队面板等其他位置标示“单独设置”也用同一个断开链接图标（悬停提示写明单独设置的档位），不用文字标签。
   - 切到更宽松的档位：可直接放行的待审批折叠为一行“切换为自动 / 全开后已放行”，其余保留；对话里出一行系统提示说明放行与剩余数量（全开时提示用赭红色）。
10. 浅色与深色两套主题，颜色以 CSS 变量定义（取值见画布 `.t-light` / `.t-dark`），组件只引用变量。
11. 网页层只负责渲染（见 `AGENTS.md`）；以上计数、额度、可否点击等状态都由 Rust 侧随 `ViewPatch` 给出，网页层不自行计算。
12. **亲手执行卡片**（需求第 9 章、AC36，v1.48；见画布第 14 页、`ui/15-UserAction-*.png`）：系统底线拦下的动作在对话里出现这张卡片，标题“需要你亲手执行”，正文写理由，下面是等宽字体的命令（或文件补丁 diff）与目标路径；按钮为“执行”（主按钮）、“复制命令”与“忽略”；没有记住选项，全开档也出现；按安全类界面处理，不加轻松元素。执行后卡片显示“你已执行”、退出码与可展开的输出（输出只给你看，不回给助手）；忽略后卡片显示“已忽略”。
13. **凭据附件提示**：附加凭据目录内的文件时弹确认“文件内容将发送给模型厂商”（取消 / 仍然附加）；私钥文件直接拒绝，提示“私钥不能作为附件发送”。
14. **运行时与模型**（需求 FR03、FR05，v1.49；画布第 1 页 Tweaks“运行时与模型菜单”、第 13 页）：所有对话的输入框工具栏显示“运行时 · 模型 ▾”（如“Claude Code · Opus ▾”）；菜单分三节：运行时（对话开始后置灰，悬停提示“要换运行时请开新对话”）、模型 · 仅本对话（可选列表 + “填写模型 ID…”）、思考强度（分段按钮，运行时不支持时整节不显示）。改选后对话中插入一行“已切换为 X”，不提示用量变化；“本对话用量”标签不显示模型。助手配置页与新建助手弹窗中，运行时 / 模型 / 思考强度为同一行三个下拉。
15. **设置 › 记住的规则**（需求 FR11、v1.61；画布未画，按设置页现有样式做）：按“永久 / 本项目 / 本对话”分组列出；每行写明动作与范围（如“执行 `npm test …`”“写 `src/`”）、记在哪个助手或项目上、创建时间，右侧“撤销”图标按钮（悬停提示“撤销”）；撤销即时生效、无需确认；空列表显示“还没有记住的规则”。审批卡片“记住”下拉里写明将记住的范围（如“本项目内 `npm test …` 不再问”）。
16. **设置 › 安全清单**（需求 FR11、v1.65）：需凭据的命令、敏感目录、可写目录三张清单的查看与增删。**界面形式待产品负责人定**（以后可能接入不同的界面）；定之前 T09 不实现这一页。能力本身在 M1 完整实现，经应用服务命令提供（技术设计 7.2c）。

## 2a 设计决定（Claude 定，2026-11-10；产品负责人可推翻）

以下是第 2 节没写到的界面细节，由设计窗口按现有规则补定（见 `AGENTS.md`“UI/UX 设计问题找设计窗口”）。和第 2 节冲突时以第 2 节为准。

1. **对话状态圆点**（侧栏与“全部对话”列表共用；状态由 Rust 侧随侧栏摘要给出，网页层不自行判断）：
   - 芥末黄 `--mus`：**等你处理**。有待审批、提问、亲手执行卡片，或回合已中断、等你选“继续 / 放弃”。
   - 赭红 `--acc`：**出错**。最近一个回合失败，且没有等你处理的事。
   - 藏青 `--brand`：**运行中**。有回合正在跑。圆点带轻微呼吸动画，系统开启“减少动态效果”或关闭轻松元素时不动。
   - 灰 `--idle`：**空闲**。没有运行中的回合，也没有待处理的事。
   - 同时满足多种时按 等你处理 > 出错 > 运行中 > 空闲 取一种。颜色不是唯一提示：悬停提示与 `aria-label` 写状态名（如“等你处理”）。
   - 画布第 1 页的“日志脱敏中间件”（赭红）按“出错”理解，“登录页改版”（灰）是空闲。
2. **助手行的“最近一条动态”**：按优先级取一条，跨这个助手参与的全部对话（私聊与项目对话）：
   1. 有等你处理的事：`<对话标题>：<待处理摘要>`，如“退款幂等：等你批准联网请求”。私聊里的就不加对话标题。
   2. 有回合在跑：`<对话标题>：工作中`，私聊里的写“工作中”。M1 不显示具体在做什么（风格样板页的“正在啃 handler.go”是远期参考）。
   3. 都没有：它最近一条发给用户的消息的首行，项目对话里的加 `<对话标题>：` 前缀。
   4. 从没说过话：不显示第二行。
   - 摘要由 Rust 侧生成，单行截断。
3. **助手行的未读数只算它的私聊**，项目对话的未读只算在项目行上，同一条未读不会两边各算一次。“最近一条动态”可以提到项目对话里的待处理事项，它是提示，不计数；全部待处理事项的总数看“待你处理”。
4. **侧栏底部在 M1 只显示“设置与运行时”**：“团队与协作方式”“审查”属于 M2，M1 不显示，也不置灰；“项目设置”这个小标题也不显示。画布保留这两项，作 M2 参考。
5. **全部对话**：
   - 在主区域打开一个列表页，不在侧栏里展开。标题为“<项目名> · 全部对话”，侧栏不高亮任何对话。
   - 每行显示状态圆点、标题、最近一条消息的首行、最近活动时间（今天的显示时刻，更早的显示日期）。
   - 按最近活动倒序，顶部一个按标题筛选的输入框。
   - 右键菜单与侧栏相同：打开 / 重命名 / 删除。
   - 滚动到底自动加载下一批，每批 50 条（`ListConversations` 分页），不做页码。
   - 没有对话时显示“还没有对话”，带“+ 新对话”按钮。画布未画，按设置页的列表样式做。
6. **重命名就地编辑的边界**：
   - 失去焦点按确认处理（与 Finder 一致）；此时内容为空则还原，不提交。
   - 最多 50 个字符，到上限后不能再输入，不弹提示。输入法组字期间不截断，组字结束后再截。
   - 去掉首尾空白后和原标题相同，就直接退出编辑，不发命令。
   - Esc 取消，回车确认。
7. **找不到路径的项目**：
   - 项目行显示划线项目名、“找不到路径”标签与行内的“重新定位”文字按钮，见 `ui/07-AddProject.png` 侧栏。项目右键菜单里也有“重新定位”。
   - 项目右键菜单：置顶 / 取消置顶、重新定位（只在找不到路径时出现）、从列表移除（FR19）。
   - 展开后下面的对话可以打开、看历史。输入框禁用，上方显示一行说明“找不到项目文件夹，重新定位后才能继续”，带“重新定位”按钮。
8. **运行时版本验证中或未通过**（T06 验收 8：状态栏不显示，只在运行时详情和诊断页标出）：只在输入框处说明，因为这里挡住了用户。
   - **验证中**：发送按钮禁用，输入框上方一行“正在检查 Claude Code <版本> 能否安全使用…”，带小转圈。已输入的内容保留。验证通过后自动恢复可发送，不自动发出。
   - **未通过**：发送按钮禁用，输入框上方一行警示色说明“Claude Code <版本> 没有通过安全检查，暂不能使用”，带“查看详情”链接，跳到设置 › 设置与运行时里该运行时的详情。
   - 已经在跑的会话不受影响。
9. **项目默认值没有界面入口**（产品负责人 2026-11-11 定，需求 v1.76）：默认审批档位、iWork 的运行时与模型、AI 审查开关与审查模型，M1 只经应用服务命令（T01 方案的 `UpdateProjectSettings`）提供修改能力，界面上不做入口：设置页没有项目一栏，侧栏底部和项目右键菜单都没有“项目设置”，输入框的档位菜单与模型菜单也不加“设为本项目默认”。这两个菜单仍然只改本对话。以后怎么改默认值不一定走界面入口，可能是问 AI 或让 AI 修改。
10. **回合一开始就失败**（2026-11-11）：
    - 运行时没能开始这一轮、助手消息内容为空时，不显示空的助手气泡。时间线里改成一行系统提示，赭红色警示图标加文字“这一轮没能开始：<原因>”，原因由 Rust 侧给出可读的说明；右侧“详情”展开后显示错误码与技术信息。
    - 已经输出了部分内容再失败的，照常显示那条助手消息，末尾加一行“这一轮中途失败：<原因>”，同样带“详情”。
    - 两种都不提供“重试”按钮（M1 没有重试命令），用户重新发消息即可。侧栏这个对话的圆点按“出错”显示（2a 第 1 条）。
11. **消息锚点**（2026-11-11；样式由产品负责人从画布“消息锚点”几组里选定：滚轮 W3 静止 + W2 展开，W2 保持原设计，只有信息卡的内容参考 S3；细节由设计窗口补定。截图 `ui/16-Anchor-rest.png`、`ui/16-Anchor-open.png`、`ui/16-Anchor-open-dark.png`）：
    - **位置**：对话区左边距，上下居中。对话不用滚动就能看完时不显示。
    - **锚点**：你的每条消息、等你处理的卡片、失败的回合。钉住的消息以后与“对话锚点”（上下文压缩）一起做，M1 不做。
    - **静止态**：三条短线表示当前位置。下面按需显示状态点：芥末黄表示本对话里还有等你处理的事，赭红表示有失败的回合，没有就不显示。
    - **展开态**：鼠标移到左边距（或键盘焦点到达）时展开成刻度滚轮。
      - 以当前位置为中心，上下最多各 4 条刻度，越靠中间越长、越远越淡。失败、等你处理用对应颜色。
      - 中间那条旁边是信息卡，样式同画布“锚点样式 S3”的预览卡：左上类型标签（你 / 等你处理 / 失败），右上时间（今天显示时刻，更早显示日期），下面是消息前两行，超出省略；卡片左侧有小三角指向中间刻度。
      - 只有刻度和信息卡：没有上下箭头按钮，也不显示“第几处 / 共几处”，纯滚轮操作。
    - **交互**（翻看方式由产品负责人 2026-11-11 选定：只看预览，点了才跳）：
      - 展开时停在当前屏幕位置对应的那一处。
      - 在刻度上滚动鼠标滚轮，每格换一处：刻度滑动一格（约 120ms），信息卡内容淡入换成新的一处。翻看过程中对话停在原地不动。
      - 触控板滑动要累计到一定距离才换一处；快速甩动时每秒最多换约 10 处。到第一处或最后一处时轻轻回弹并停住，不循环。
      - 点中间那条或信息卡：跳到那条消息，高亮 1 秒，滚轮收起。点其他刻度：直接跳过去。
      - Esc 立即收起，对话不动；鼠标移开 300ms 后收起，对话也不动。
      - ⌥↑ / ⌥↓ 不经滚轮，直接逐处跳转对话。
      - 不展开时，当前位置跟随对话滚动。
      - 系统开启“减少动态效果”时，去掉滑动和淡入动画。
    - **数据**：锚点列表由 Rust 侧随视图给出，包括消息编号、类型、时间与消息前两行，网页层不自行计算。跳到还没加载的旧消息时，需要能“以某条消息为中心加载一段”，由 T09 的时间线分页提供。
12. **侧栏宽度**（2026-11-11）：外宽 **296px**（含左右内边距与右边框，按 `box-sizing: border-box` 计），以画布截图为准。画布源码里写的 `flex: 0 0 264px` 是内容宽，加上内边距与边框后实际渲染为 296px；`design-system/tokens.css` 的 `--sidebar-w` 已同步改为 296px。M1 不可拖动调宽。
13. **助手出错时的表情**（产品负责人 2026-11-11 从画布“助手出错表情”三种里选定 B“做错事”）：新增状态 `sorry`，素材 `design-system/characters/*-sorry.svg`（四个角色各一个）：眼睛往下瞟、尴尬地抿嘴、头顶冒一滴汗。最近一个回合失败、且没有等你处理的事时显示；用户再发消息、新回合开始后换回对应状态。不浮动、不弹跳；**不用 `angry`**（那是连戳三下的玩笑）。和其他表情一样随状态变化，关闭“轻松元素”时也照样显示。出错的其他提示不变：侧栏对话圆点为赭红（2a 第 1 条），时间线里一行“这一轮没能开始 / 中途失败：<原因>”（2a 第 10 条）。

### 3.3 助手形象

- 每个助手是一个简笔小人，形状各不相同（阿森：歪蛋形 + 三根呆毛；林岚：云朵 + 圆眼镜；老周：吐司 + 小帽 + 八字胡；新建助手默认圆团子，颜色可在配置里选）。用矢量绘制，颜色取 `--ch*`，深浅色自动切换。
- 表情随状态变化：空闲（眯眼微笑）、工作中（专注吐舌 + 轻微上下浮动摇摆）、等你（头顶“?”）、完成（弯眼大笑 + 星星，出现时弹一下）、出错（眼睛往下瞟、尴尬抿嘴、头顶一滴汗，见 2a 第 13 条）。
- 鼠标悬停：蹦一下、歪身、换成眨眼笑，头顶冒“嗨”。
- 点击（戳一下）：跳得比悬停更高。2 秒内连续戳 3 次：假装生气约 1.5 秒（鼓腮、皱眉、脸颊变红），之后恢复原状态。戳头像不触发打开对话以外的任何业务操作。
- **眼睛跟随鼠标（只限侧栏头像）**：鼠标在侧栏范围内移动时，侧栏每个助手的眼珠朝鼠标方向偏移（最多 1.5px），用来直观看出指向了谁；鼠标离开侧栏后回正。实现要求：只监听侧栏的 pointermove，每帧最多计算一次（requestAnimationFrame 合并），只改 transform；窗口失去焦点、系统“减少动态效果”时停用。对话区与其他位置的头像不跟随。
- 所有动画在系统开启“减少动态效果”时停用；动画只用 transform，不得拖慢 16ms 帧。
