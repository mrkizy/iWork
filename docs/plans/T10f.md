## 0 一页总览

Claude Code 首次接入时，iWork 列出用户本机给它配的 MCP 服务器、技能、插件，用户勾选后导入。导入之后成员会话里只有导入过的这些，没导入的不出现。

| 导入什么 | 从哪读 | 存到哪 | 会话怎么拿到 |
| --- | --- | --- | --- |
| 技能（用户级的，和插件里的） | 技能目录的文件 | 复制进只读区 `imports/<运行时>/<一代快照>/`，目录由 iWork 自己拼成插件的样子；凭据文件范围内的不带（等 PD-9） | `--plugin-dir`（`SessionSpec.plugin_dirs`） |
| MCP 的启动配置（命令、参数、地址） | `~/.claude.json`、插件的 `.mcp.json` | 系统钥匙串，一台服务一条（等 PD-1） | 适配器从钥匙串取出来，放进 ACP `session/new` 的 `mcpServers` |
| MCP 的环境变量、请求头的**值** | **不读** | 用户在 iWork 里重填，进系统钥匙串，一个键的一版值一条 | 同上 |
| MCP 的名字、要填值的键名、每个键现在用哪一版 | 同启动配置 | 数据库（事件与投影） | 后台拼 `SessionSpec.mcp` |
| 插件里的 hook、命令、子代理、可执行文件、设置 | 不读 | 不导入 | — |

五条最要紧的保证：

1. **不读 MCP 配置里 `env`、`headers` 的值**。解析时直接跳过，不变成程序里的任何一个值（第 4 节 R1）。
2. **MCP 配置里读出来的值，除了名字和键名，只进钥匙串**。数据库、事件、日志里搜不到（R2）。命令行参数和地址里可能写着密钥，iWork 分不出来，一并当密钥待。这等于 iWork 读了、也在钥匙串里存了可能带密钥的参数，要产品负责人明确接受（PD-1），接受之前 MCP 导入不启用。
3. **用户的 hook 不随导入进会话，技能也不能给自己放行**。导入区里的插件目录是 iWork 自己拼的，只往里放技能目录；`SKILL.md` 的 frontmatter 只留一张白名单里的键（R4、R5）。
4. **用户确认的是哪一份，存进去、交出去的就是哪一份**。查询结果里每一项带指纹，导入时现读一次、指纹对不上就拒；会话读得到的东西都是写一次不改的版本，只由事件切换（3.4 的四条约定，R17–R20）。
5. **导入的东西出了问题，撤得回来**。移除先挡住新的会话，再把还用着它的会话连进程一起停掉；不需要钥匙串可用（R16）。

技能文件是原样复制的，这一点要说清：范围内的凭据文件（3.2 那张表）不带；范围外的（普通名字的文件里写着 token）iWork 认不出，会进 Agent 读得到的只读区。这放宽了安全不变量第 1 条，不是登记一条已知限制就能过的，要产品负责人明确接受（PD-9），**接受之前技能与插件条目导不了**。

本方案新加的东西：一个命令 `RemoveImportedConfig`、一个事件 `ImportedConfigRemoved`、一个错误码、一个消息 `McpLaunchConfig`（钥匙串里启动配置的编码）、一个端口 `LocalConfigSource` 和它的 Claude 实现（新 crate `iwork-import-claude`）、`iwork-host` 的钥匙串实现、`iwork-core::local_import` 一个纯函数模块。协议里别的都已经在了（T02 定的），只加字段。

### 1.3 约束

- 不读取、不保存、不转发任何凭据或 token（AGENTS.md 安全不变量第 1 条）。MCP 密钥只进系统钥匙串，由用户重新填写，数据库只存引用（FR20、技术设计 9.5 第 4 条）。**放宽这一条的地方不能只登记成已知限制**：要产品负责人明确接受，接受之前对应的能力不启用。本方案里这样的地方有两处，PD-1 与 PD-9。
- 成员会话不加载未经导入的 MCP、技能与插件，不运行用户的 hook，不沿用用户的权限模式（需求 8.4、AC35）。iWork 的审批不能被厂商 CLI 的放行规则放宽（安全不变量第 2 条）。
- 导入区 `imports/` 是只读区：Agent 可读、可执行里面的脚本，不可写（需求 v1.64；技术设计 5.1、7.0）。
- 环境变量原样继承（T06 P14），自动记忆一律关闭。本卡不动这两条。
- 厂商差异收在适配层：`iwork-domain`、`iwork-core` 里不出现 Claude 的文件名和键名（AGENTS.md 架构约定）。判定（哪些文件算凭据、哪些条目能导）在核心，是纯函数；适配层只读文件、照判定做。
- 一次命令 = 追加事件 + 更新投影，同一事务，单写者（技术设计 5.2）。事务之外的东西（文件、钥匙串）怎么和它对齐，见 3.4 的四条约定。
- 能力与界面分离：导入、移除、填密钥、查询都是应用服务的命令与查询，规则不放界面层（需求 7.2）。
- 安全设计原则：先找现有机制，覆盖不了交产品负责人定，不为堵一个缺口加一串新机制（需求 v1.50、v1.69）。
- 厂商 CLI 的行为只认 `t0-findings.md` 里验过的；没验过的列在第 6 节，结果出来之前相应的步骤不合入。

### 1.4 厂商文档的说法与本机看到的形状（都还不算事实，第 6 节逐条实测）

官方文档（code.claude.com/docs，2026-11-12 查）：

- MCP 有三个范围：user（`~/.claude.json`）、local（`~/.claude.json` 里 `projects.<项目路径>.mcpServers`，`claude mcp add` 的默认范围）、project（仓库根 `.mcp.json`）。条目的字段：stdio 用 `command`、`args`、`env`；远程的用 `type`（`http`、`sse`、`ws`）、`url`、`headers`，另有 `headersHelper`、`oauth`。`command`、`args`、`env`、`url`、`headers` 的值里 `${VAR}` 会被展开。
- `-p` 加 `--mcp-config` 时，CLI 等服务器连上再跑第一轮，最多等 `MCP_TIMEOUT`（默认 30 秒）。校验不过的条目被跳过，进 `system/init` 的 `mcp_server_errors`，进程照常。`-p` 下走不了 OAuth 登录。
- `SKILL.md` 的 frontmatter 里，`allowed-tools` 是「调用这个技能的那一轮里，这些工具不用问」，文档原话还有一句「a repository's skill can grant itself tool access」；`hooks` 是「技能被调用时注册、此后整条会话都在跑」的 hook。
- 技能正文里的 `` !`命令` `` 在技能内容交给模型之前执行，不弹询问，先过权限规则，不是 allow 就让这次技能调用失败；`allowed-tools` 可以预先放行它。设置键 `disableSkillShellExecution: true` 把这些命令换成一句占位文字，对用户、项目、插件来源的技能都生效。文档没写 PreToolUse hook 管不管这类命令。
- 插件根目录下会被自动发现的有：`skills/`、`commands/`、`agents/`、`hooks/hooks.json`、`.mcp.json`、`.lsp.json`、`output-styles/`、`workflows/`、`themes/`、`monitors/`、`bin/`（进 Bash 的 PATH）、`settings.json`。`.claude-plugin/plugin.json` 只有 `name` 必填。插件里技能的名字是 `<插件名>:<技能名>`。
- `--plugin-dir` 可以重复给；`system/init.plugins` 每项有 `name`、`path`，文档没写 `path` 长什么样。

已经验过、和本卡直接有关的一条（`t0-findings.md` 2.4，R1x 的 x2，2.1.322）：`dontAsk`、不配 hook 时，`cat` 工作目录内的文件这类只读命令 CLI 不问、直接执行。所以「CLI 的权限层不放行就不执行」只对 CLI 要问的命令成立。

## 2 分层与数据流

```text
客户端（网页只渲染；client-core 拼意图）
  │ ListLocalConfig / ImportLocalConfig / RemoveImportedConfig / SetMcpSecret / DismissLocalImportPrompt
  ▼
应用服务（iwork-app）：受理、定先后（每个运行时一把锁）；值只在这里从命令里拿出来、交给 SecretStore
  │                    │                              │                      │
  ▼                    ▼                              ▼                      ▼
iwork-core::local_import   LocalConfigSource              SecretStore            会话线表（T10a）
（纯函数：plan_import、     （端口 iwork-ports；            （端口；实现           撤回时停掉
  admit_file、fingerprint、  实现 iwork-import-claude）       iwork-host::keychain） 还引用着的会话
  mcp_name、readiness）     读 ~/.claude.json、技能与插件目录；拼快照进 imports/
```

| 层 | 放什么 | 不放什么 |
| --- | --- | --- |
| `iwork-core::local_import`（新模块） | `plan_import`（勾选的条目能不能导、会不会撞名）、`admit_file`（一个文件带不带：凭据文件范围表加 T10d 的私钥表）、`fingerprint`、`mcp_name`、`readiness` | 不读文件、不认识 Claude 的任何键名 |
| `iwork-ports`（`local_import` 新模块；`secret` 加两个函数） | `LocalConfigSource`、`FileAdmit` 两个 trait 与数据类型；`mcp_launch_name(id)`、`mcp_key_name(id, 键名, 版本)`：钥匙串里的名字只在这里拼，应用服务与适配器都调它 | — |
| `iwork-import-claude`（新 crate，适配层） | Claude 的配置长什么样：来源表、选择性解析、frontmatter 白名单、快照怎么拼、文件怎么持久化 | 不碰数据库、不碰钥匙串；不自己判哪个文件算凭据（判定由上面传进来） |
| `iwork-host::keychain` | `SecretStore` 的系统钥匙串实现 | 不知道 MCP 是什么 |
| `iwork-app` | 四个命令、一个查询的受理；每个运行时的导入锁 | 不解析 Claude 的文件 |
| `iwork-agent-acp` | 把 `McpServerRef` 加上钥匙串里的内容，变成 ACP 的 `McpServer` | 不落盘、不记日志 |
| `iwork-bridge-claude` | 把收到的 `mcpServers` 写成 `mcp.json`；核对 `init.mcp_servers` | 不认识钥匙串 |

`iwork-import-claude` 的依赖：内部 `iwork-ports`、`iwork-domain`、`iwork-rootfs`；外部 `serde`、`serde_json`、`sha2`、`thiserror`。它不依赖 `iwork-core`：要用核心的判定，由应用服务把 `FileAdmit` 的实现传进去。`scripts/deps-policy.toml` 加一节，`iwork-daemon` 的 `internal` 加它。

## 3 设计

### 3.1 发现：读哪些文件、取哪些键

`iwork-import-claude::sources` 里一张来源表，发现只打开表里的文件，只取表里的键：

| 来源 | 打开的文件 | 取 | 不取 |
| --- | --- | --- | --- |
| user 范围的 MCP | `<配置目录>/.claude.json` | 顶层 `mcpServers` 每一项的 `type`、`command`、`args`、`url`；`env`、`headers` 的**键名**；有没有 `headersHelper`、`oauth` 这两个键 | `env`、`headers` 的值；这个文件里别的顶层键全部跳过 |
| 用户级技能 | `<配置目录>/skills/<目录>/SKILL.md` 与那个目录下的文件 | frontmatter 的 `name`、`description`；要带的文件的清单与内容摘要 | `skills/synced/`（厂商账号同步下来的）；3.2 判成不带的文件 |
| 已装的插件 | `<配置目录>/plugins/installed_plugins.json`；每个 `installPath` 下的 `.claude-plugin/plugin.json`、技能目录、`.mcp.json` | 插件名；技能同上一行；MCP 同第一行 | 插件里别的一切 |

- `<配置目录>`：后台环境里有 `CLAUDE_CONFIG_DIR` 就用它，没有用 `~/.claude`；`.claude.json` 在配置目录是默认值时位于家目录（待 D1 核对）。
- **表外的文件一概不打开**：`.credentials.json`、`settings.json`、`projects/`、系统钥匙串都不在表里。local 范围和仓库里的 `.mcp.json` 列不列，等 PD-3。
- **怎么做到不读值**。解析用 `serde` 的选择性反序列化：目标结构只声明要的字段，别的字段落到 `IgnoredAny`；`env`、`headers` 用一个只收键名的访问器，值一律交给 `IgnoredAny` 吃掉。文件的字节会经过进程内存（要读文件就免不了），但值不会变成任何一个 Rust 值，函数返回之后就没有了。这和 T06 读 `auth status` 的做法是同一种（T06 方案第 10 节）。错误只带文件名和键的路径，不带内容。
- **读文件走接缝**：`trait LocalFiles { read(path), list(dir), kind(path) }`，生产实现是 `std::fs`，测试实现记下每一次打开的路径，还能在指定的那一次读之后把内容换掉。「只打开表里的文件」「来源被换掉之后不会存错」都靠它测。
- **`discover()` 一次把要用的都读出来**：每个 MCP 条目带着它的启动配置（`McpLaunch`：命令、参数、地址、键名，没有值）；每个技能条目带着要带的文件清单与内容摘要。导入时不再为同一个条目去读第二遍来源的配置文件（3.4 约定三）。
- **条目的 id** 由来源拼出来，重启不变：`mcp:user:<名字>`、`skill:user:<目录名>`、`plugin:<插件键>`、`mcp:plugin:<插件键>:<名字>`、`skill:plugin:<插件键>:<目录名>`。插件自带的 MCP 作为普通的 MCP 条目列在 MCP 一组里，来源写插件名，不嵌在插件那一行下面（数据上不做嵌套；界面怎么摆见第 11 节给设计窗口的问题）。
- **导不了的条目照样列出来，写明原因**（`blocked_reason`），不悄悄藏掉：

| 情形 | 原因文字 |
| --- | --- |
| `type` 是 `ws`、`sdk`，或有 `url` 却没有 `type` | 「这种连接方式 M1 不支持」 |
| 有 `headersHelper` 或 `oauth` 键 | 「用了动态请求头或 OAuth 配置，M1 不支持导入」 |
| MCP 名字不合规（3.3） | 「名字里有 iWork 不接受的字符」或「名字以 iwork 开头」 |
| 插件的 MCP 配置里有 `${CLAUDE_PLUGIN_ROOT}` 之外的 `${CLAUDE_…}` 变量 | 「配置引用了 iWork 不提供的插件变量」 |
| 插件是「根目录一个 SKILL.md」的布局 | 「这种插件布局 M1 不支持」 |
| 技能目录名不合规、`SKILL.md` 的 frontmatter 看不懂（3.2）、超过大小上限、里面有私钥 | 各自点名 |
| 技能或插件条目，而 PD-9、PD-5 的门槛还没开（3.2） | 「技能导入还没启用」 |
| MCP 条目，而 PD-1 的门槛还没开 | 「MCP 导入还没启用」 |

- 不列出的：用户的 hook、权限模式、插件里的 `commands/`、`agents/`（FR20：不导入）；`commands/` 目录下的旧式命令。

### 3.2 技能：一代一份快照，iWork 自己拼

**目录**（`<数据目录>/imports/<运行时 kind>/`；kind 是 `runtimes.kind` 那个不透明字符串）：

```text
imports/claude/
  g-<ULID>/                       一代快照，建好之后不再改
    MANIFEST                      这一代里每个文件的相对路径与大小，最后写
    imported/                     用户级技能合成的一个插件
      .claude-plugin/plugin.json  iWork 写的，内容只有 {"name":"imported"}
      skills/<技能目录名>/…
    <插件名>/                     每个来源插件一个，保住原来的名字（技能名仍是 <插件名>:<技能名>）
      .claude-plugin/plugin.json  iWork 写的，只有 name
      skills/<技能目录名>/…
  .tmp-<随机>/                    正在建的；建完改名成 g-…
```

交给会话的 `plugin_dirs` = 当前这一代里每个插件子目录的绝对路径（排过序）。逐个给，不给上一级目录：T0f 的 V2 验过的是「一个插件根」这种给法；「给一个放了多个插件的目录」只在帮助和文档里写着，没验过。

**哪些文件带、哪些不带**（`iwork-core::local_import::admit_file(相对路径, 内容) -> Take | Skip(原因) | RefuseItem(原因)`，纯函数；应用服务把它包成 `FileAdmit` 传给 `discover` 与 `build_snapshot`，两处用的是同一个判定）：

| 序 | 条件（名字比较不分大小写） | 结果 |
| --- | --- | --- |
| 1 | `private_key::matches(名字, 内容)`（T10d 方案 3.4 的那张表，交付方 T10d） | `RefuseItem`：这个技能整个不导，原因点名文件。和附件「私钥一律拒绝」是同一条规则、同一个函数 |
| 2 | 路径上任何一级的名字以 `.` 开头（`.env`、`.env.local`、`.npmrc`、`.netrc`、`.git/`、`.aws/` 等） | `Skip` |
| 3 | 文件名等于底线凭据清单里某个文件条目的文件名（取自 `protected_paths().credential`，T07 的那一份，T10d R1 用的同一个来源） | `Skip`。现在清单里的都以 `.` 开头，已经被第 2 行盖住；留这一行是为了清单以后加了不带点的名字时这里自动跟上 |
| 4 | 文件名去掉扩展名后恰好是 `credentials`、`credential`、`secrets`、`secret`、`token`、`tokens`、`apikey`、`api_key`、`api-key`、`password`、`passwords` | `Skip` |
| 5 | 扩展名是 `.keystore`、`.jks`、`.kdbx`、`.token`、`.secret`、`.secrets`、`.credentials` | `Skip` |
| 6 | 剩下的 | `Take` |

- 这张表就是「凭据文件的范围」。范围内的不带，被略过的文件按相对路径列进这一项的 `notes`（「不带：.env、config/credentials.json」），用户勾选之前看得到。宁严勿松：`secrets.md` 这种讲解文档也会被第 4 行略过。
- **范围外的认不出**：`config.json` 里写着 token、脚本里写死了密钥，iWork 不看内容里有没有密钥（看也只能靠猜），会原样复制。这就是 PD-9 要产品负责人接受的那个例外。
- **门槛**：`iwork-core::local_import` 里一个常量 `SKILL_IMPORT_ENABLED`，默认 `false`。为 `false` 时 `plan_import` 对技能、插件条目一律拒（原因「技能导入还没启用」），`discover` 给它们填同样的 `blocked_reason`。把它改成 `true` 的那次提交要同时满足三样：PD-9 有产品负责人的明确接受（提交信息里引用）、PD-5 定了并且它要的实测格通过（下面「技能正文里的命令」）、`skill_token_files_never_reach_imports` 通过。MCP 的导入不受它管（它有自己的门槛，PD-1）。

**怎么拼**（`LocalConfigSource::build_snapshot(plan, admit, dest)`，`dest` 是那个 `.tmp-` 目录，必须还不存在，`mkdir` 独占创建；写文件经接缝 `trait SnapshotFs { create_dir, write_file, sync_file, sync_dir, rename }`，生产实现是 `std::fs`）：

1. 留下来的条目从上一代复制（上一代是 iWork 自己写的，只有普通文件和目录）。不从来源重读：没让重导的技能保持导入那一刻的样子。
2. 新导入、重新导入的条目从来源复制。来源的技能根目录先解析一次链接（`~/.claude/skills` 本身、或单个技能目录是链接都很常见）；解析之后，用 `iwork-rootfs` 的读法（ADR-0010，路径上任何一级都不跟随链接）走这棵树：
   - 只复制普通文件和目录。链接、FIFO、socket、设备文件都略过，数目记进这一项的 `notes`（「略过 2 个链接」）。
   - 每个文件过 `admit`（上面那张表）。
   - 上限：一个技能 2000 个文件、32 MiB；整代快照 256 MiB（三个具名常量，放 `iwork-import-claude::limits`）。超了 → 这一项不导，原因写明超了哪个。
   - 文件内容原样，权限只保留「可执行」这一位（0644 或 0755）。
   - **边复制边算摘要**（对每个带过去的文件：相对路径、可执行位、内容，和 `discover` 算摘要是同一个函数），每一项算出来的摘要交回给调用方；它和用户确认时的那个对不上，整次导入作废（3.4 约定三）。
3. `SKILL.md` 过 frontmatter 白名单（下面）。
4. `plugin.json` 由 iWork 写，只有 `name`。来源插件的 `plugin.json` 不复制。
5. **持久化的先后**（照 T02 方案 2.10「先 `fsync` 临时文件、改名、再 `fsync` 目录」的写法；macOS 上用不用 fullfsync 跟存储读同一个开关）：
   1. 每个文件写完 `sync_file`；
   2. 写 `MANIFEST`，`sync_file`；
   3. 从最深的目录往上，逐个 `sync_dir`，直到 `.tmp-…` 本身；
   4. `.tmp-…` 改名成 `g-<ULID>`（同一个目录下改名，原子）；
   5. `sync_dir` 上一级目录 `imports/<kind>/`；
   6. 这五步都返回成功之后，调用方才提交事件。之后这一代只读不写。

**启动恢复**（后台启动时、放开任何会话之前，排在 T04 的启动恢复里；先后不能换）：

1. 读投影里这个运行时的当前快照名。
2. 核实它完整：目录在、`MANIFEST` 在、清单里每个文件都在而且大小相等。
3. 完整 → 清扫：`imports/<kind>/` 下名字是 `g-*`、`.tmp-*` 而又不是当前这一代的目录都删；别的名字不碰、记一条日志。
4. 不完整 → **什么都不删**。这个运行时记「快照损坏」（内存里的状态，每次启动现查，不进投影）：`plugin_dirs` 给空，技能条目在列表里标「快照损坏，请重新导入」，写错误日志与一条审计。用户重新导入会生成新的一代。不自动退回上一代：上一代里可能有已经移除的技能。

**为什么是「自己拼」而不是「复制插件再删掉 hook」**：文档列的自动发现位置有十二种，还会再加。删掉认识的那几种，新版本多出来一种就漏了。只放 `skills/` 这一种，别的无论叫什么都进不来。

**frontmatter 白名单**（`iwork-import-claude::skill_md::filter(bytes) -> Result<Filtered, Unreadable>`，纯函数）：

- 留：`name`、`description`、`when_to_use`、`argument-hint`、`arguments`、`disable-model-invocation`、`user-invocable`、`paths`、`context`、`agent`、`background`、`disallowed-tools`、`license`、`metadata`、`compatibility`、`version`。
- 去掉：表外的一切。眼下已知的有 `allowed-tools`（让工具免询问）、`hooks`（注册 hook）、`model`、`effort`（iWork 每次都显式指定模型与思考强度，技术设计 9.6）、`shell`。去掉了哪些键写进这一项的 `notes`，导入前用户看得到。
- 做法：frontmatter 是开头两行 `---` 之间的那一段。按行切成「顶格的 `键:` 起头、到下一个顶格键之前」的块，整块留或整块去，正文原样。不引 YAML 库。
- **看不懂就不导**：开头是 BOM、有单独的 CR、顶格行不是 `键:` 的样子（带引号的键、`<<:` 合并键、`{…}` 流式写法、制表符缩进）→ `Unreadable`，这个技能不导，原因写「SKILL.md 的开头看不懂」。宁可少导一个，不猜。
- 没有 frontmatter 的 `SKILL.md` 原样复制。技能目录里别的 `.md` 不处理（只有 `SKILL.md` 的开头有这层含义）。

**技能正文里的命令（`` !`命令` ``）** 白名单管不到（它在正文里）。第 1 版写的是「去掉 `allowed-tools` 之后它过不了权限规则，命令不执行」，这句话太宽：CLI 的权限层只拦它要问的命令，`cat` 这类只读命令它不问（1.4 引的 x2）。所以现在的说法是：

- 去掉 `allowed-tools` 之后，**CLI 要问的命令**（写文件、别的程序）照文档不执行（待 K3a）；**CLI 不问的只读命令**多半照样在技能加载时执行，读到的内容直接进模型上下文，不经 iWork 审批、没有审计（待 K3e）；读不读得到底线目录看这类命令在不在沙箱里跑（待 K3f）。
- 干净的办法是会话设置里加 `disableSkillShellExecution: true`（PD-5 的 a，待 K3c）。
- 这一条定下来、对应的格子通过之前，`SKILL_IMPORT_ENABLED` 不开。

### 3.3 MCP：名字进数据库，别的进钥匙串

**一台导入的 MCP 由三样东西组成**：

| 东西 | 内容 | 存在哪 |
| --- | --- | --- |
| 登记 | `mcp_server_id`（每次导入新生成的 ULID）、条目 id、名字、要填值的键名、每个键现在用哪一版 | 事件与投影 |
| 启动配置 | 消息 `McpLaunchConfig{transport, command, args, url, env_keys, header_keys}` 的 Protobuf 二进制 | 钥匙串，名字 `mcp/<mcp_server_id>/launch`（等 PD-1）。`mcp_server_id` 每次导入都是新的，所以这一条写一次、不会被覆盖 |
| 一个键的一版值 | 用户填的 | 钥匙串，名字 `mcp/<mcp_server_id>/key/<键名>/<版本 ULID>`。每填一次是新的一版、新的一条，不覆盖旧的 |

- 启动配置用 Protobuf 编码，是因为写它的（应用服务）和读它的（适配器）不在一个 crate 里，两边都已经依赖 `iwork-proto`；钥匙串里存的东西升级之后还得读得出来，进了兼容契约就只增不改。
- **名字**：`[A-Za-z0-9_-]{1,64}`，不以 `iwork` 开头（留给 iWork 自己的协作 MCP，需求 8.1）。同一个运行时下不重名。它会出现在工具名 `mcp__<名字>__<工具>` 和审批卡片上。插件自带的 MCP 用配置里的名字，撞名时这一项导不了，原因点名和谁撞。
- **env 与请求头的每个键都要用户填值**，iWork 不判断哪个是密钥、哪个只是普通配置（判断就得读值）。代价和别的做法见 PD-2。
- **齐不齐**（`readiness`，纯函数）：每个键在投影里都有当前版本 → `Ready`；否则 `MissingKeys(键名…)`。只有 `Ready` 的进 `SessionSpec.mcp`。
- **重新导入 = 换一台**：同一个条目再导一次（来源变了，或用户就是想重来），生成新的 `mcp_server_id`，键全部重填；旧的那台走撤回（3.4 约定四）。目的：`~/.claude.json` 里那一项的命令被人改过之后，新命令拿不到用户以前填的密钥，用户得看着新的启动方式重新填一遍。
- **插件自带的 MCP**：配置里的 `${CLAUDE_PLUGIN_ROOT}` 在导入时换成那个插件的 `installPath`。程序留在用户的插件目录里跑，iWork 不复制它（第 9 节 L4）。
- **`mcp_read_only`**（哪些 MCP 工具声明了只读）：M1 给空集，所有 MCP 工具在手动、自动档都询问（T07 方案 3.1 写的安全侧做法）。等 PD-6。

### 3.4 命令与查询

#### 四条约定（导入、移除、填值三个命令都照它走）

文件和钥匙串不在数据库事务里。第 1 版只写了「先落文件和钥匙串、后提交事件，崩了清扫」，漏了四件事：对象会不会被覆盖、算的时候看到的状态提交时还作不作数、用户确认的和实际存的是不是同一份、「落了」算不算持久。下面四条把它们一次立住。

| # | 约定 | 目的 |
| --- | --- | --- |
| 一 | **写一次、带版本**。会话读得到的对象只有三种：一代快照（`g-<ULID>`）、一台 MCP 的启动配置（名字里是每次导入新生成的 `mcp_server_id`）、一个键的一版值（名字里有版本）。写了不改、不覆盖 | 提交之前写的东西，没有任何会话读得到 |
| 二 | **先持久、后引用；事件是唯一的切换点**。对象写好并且持久化之后（文件照 3.2 第 5 步；钥匙串以 `set` 返回成功为准）才提交事件。会话只经投影里的引用找对象 | 提交失败、崩溃、掉电，留下的只会是没被引用的对象；投影指着的对象一定是完整的 |
| 三 | **提交时核对**。(a) 改动导入状态的三种事件都带 `base_revision`：受理时读到的这个运行时的「导入修订号」。写线程投影时核对 `runtimes.import_revision` 还等于它，不等就让整条命令回滚，回 `CONFLICT`（`exec_hit`，和 T10d 方案 3.6 让写线程把关是同一个机制）；等的话把它改成这条事件的序号。(b) 用户确认过的内容带**指纹**：`ListLocalConfig` 的每一项带 `fingerprint`，`ImportLocalConfig` 把它带回来；受理时对来源只 `discover()` 一次，用这一次读到的内容算指纹、也用这一次读到的内容去存；对不上就拒 | (a) 两条命令穿插时，后提交的那条不会把先提交的结果盖掉（移除掉的不会被一条算在前面的导入带回来）。(b) 用户看着 A 点的确认，存进去、拿到密钥、在沙箱外起来的不会是 B |
| 四 | **退场的先后**：先提交（新拼的 `SessionSpec` 里没有它）→ 把还引用着它的会话连进程一起停掉 → 删对象 | 撤回不只是「下一回合生效」 |

**每个运行时一把锁**（`iwork-app::import_gate`，异步互斥）：导入、移除、填值的整条命令在锁里做，从读状态到撤回做完。它只是让三种命令排队、不白算；保证靠约定三 (a)，锁没了、多了一个调用方，写线程照样挡得住。

**先后怎么排**：

| 两件事 | 先后怎么定 | 结果 |
| --- | --- | --- |
| 导入、移除、填值之间 | 锁里排队；写线程按 `base_revision` 核对 | 后提交的那条看到的一定是前一条之后的状态；看到旧状态的被拒，什么都没变（它写的对象没人引用，照约定二处理） |
| 开会话 与 任何改动 | 开会话不拿锁，读的是已提交的投影 | 读到的引用要么全是改动之前的、要么全是之后的。读到之前的而对象已经被删 → 钥匙串取不到 → 开会话失败并点名（3.6），不会拿到别的值；再开一次读到的就是新的 |
| 开会话 与 撤回 | 会话线表的一把锁（下面「撤回」第 2 步） | 撤回提交之前拼好 `SessionSpec`、之后才登记的会话，登记那一刻被认出来、当场停掉 |

**指纹怎么算**（`iwork-core::local_import::fingerprint`，纯函数，SHA-256 的十六进制）：MCP 条目 = 名字 + `McpLaunchConfig` 的编码（含参数、地址、键名）；技能、插件条目 = 名字 + 内容摘要 + `notes`。它只出现在 `ListLocalConfigResult` 和 `ImportLocalConfig` 里，不进事件、不进数据库；帧日志的遮盖表里和 `launch_preview` 一起遮掉（参数里要是有弱口令，摘要能被离线猜出来）。

#### 命令

| 命令 / 查询 | 受理时做什么（按先后；带 ★ 的在导入锁里） | 失败 |
| --- | --- | --- |
| `ListLocalConfig{runtime_id}` | `discover(admit)`；和投影里已导入的行合并：算 `imported`、`sync`、`missing_keys`、`fingerprint`；已导入而来源里找不到的也列出来（`SOURCE_MISSING`）。MCP 的 `launch_preview` 来自这一次 `discover`。**不写任何东西** | 来源读不了 → `UNAVAILABLE`，点名文件 |
| `ImportLocalConfig{runtime_id, selections}` ★ | ① 读投影，记下导入修订号 R；② `discover(admit)` **一次**；③ 每个勾选项：条目在、现算的指纹等于带来的指纹；④ `plan_import(当前状态, 发现结果, 勾选)`；⑤ 有技能或插件 → `build_snapshot`，每项交回的摘要要等于 ② 里的；⑥ 每台 MCP：用 ② 里那一份启动配置，新生成 `mcp_server_id`，写钥匙串的 `launch`；⑦ 一次提交：`LocalConfigImported{base_revision: R, …}`（带快照名，每项的 `mcp_server_id`、键名、来源摘要、在快照里的位置），还没提示过的话同一次提交里加 `LocalImportPrompted`，被换掉的旧 MCP 名下记住的规则一起处理（等 PD-7）；⑧ 有被换掉的旧 MCP → 撤回（下面） | ③ 对不上、④ 有一项导不了、⑤ 摘要对不上 → `LOCAL_IMPORT_REJECTED`，`details` 里每个被拒条目一条原因（指纹对不上的原因是「来源在你确认之后变了，请刷新」）；⑤ ⑥ 出错、⑦ 被拒（`CONFLICT`）→ 什么都没变：这次写的钥匙串条目删掉，`.tmp-` 或新一代目录删掉（删不掉的由启动清扫收） |
| `RemoveImportedConfig{runtime_id, item_ids}` ★ | ① 读投影，记下 R；② 有技能或插件 → `build_snapshot`（只留剩下的，都从上一代复制；一个都不剩就没有新快照）；③ 一次提交：`ImportedConfigRemoved{base_revision: R, …}`；④ 撤回（下面）；⑤ 删这些 MCP 的钥匙串条目，删不掉只记一条审计（点名钥匙串里的名字）。③ 成了命令就算成功，④ ⑤ 的失败不改这个结果 | 条目不是已导入的 → `NOT_FOUND`；③ 被拒 → `CONFLICT`，新建的目录删掉 |
| `SetMcpSecret{mcp_server_id, key_name, value}` ★ | ① 读投影，记下 R；这台 MCP 在、`key_name` 在它登记的键名里；② 生成新的版本号；把 `value` 从命令里**挪**出来（`mem::take` 再 `into_bytes`，不复制）包成 `SecretValue`，`SecretStore::set` 到**新的名字**（带这个版本）；③ 提交 `McpSecretSet{…, version, base_revision: R}`；④ 提交成功后删上一版的那一条（删不掉记审计） | ① → `NOT_FOUND` / `INVALID_ARGUMENT`；② → `SECRET_STORE_FAILURE`，不提交；③ 被拒 → `CONFLICT`，把刚写的这一版删掉。任何失败之后，投影指着的还是上一版，新开的会话用的也是上一版 |
| `DismissLocalImportPrompt{runtime_id}` | 提交 `LocalImportPrompted`（已经提示过就什么都不做，照常成功） | — |

- **整条拒绝，不做「能导的先导」**：一条命令要么全成、要么什么都没变，界面只要把被拒的那几项标出来让用户去掉勾，或者刷新后重新确认。
- **重试与重放**：
  - 同一个 `command_id` 再来：受理入口先查 `commands` 表（T10a 交付），命中就回上一次的结果，不再写文件、不再写钥匙串。
  - 上一次崩在提交之前：`commands` 表里没有它，重试等于从头做一遍，生成新的快照名、新的 `mcp_server_id`、新的版本号；上一次留下的对象没人引用（快照由启动清扫删；钥匙串条目留着，L6）。
  - `CONFLICT` 可以重试（`retryable = true`）：客户端重新 `ListLocalConfig`，用户看到的是新状态。
  - 重放事件（重建投影）只动数据库，不碰文件和钥匙串。`base_revision` 的核对在重放时照样做，事件是按原来的先后来的，一定对得上。
- **移除先提交、后删钥匙串**：先删的话钥匙串出故障时移除就走不通，而移除正是出事时要用的那条路。

#### 撤回（约定四的做法）

什么算退场：被移除的 MCP、被重新导入换掉的旧 MCP（它们的 `mcp_server_id`）；移除技能或插件时被换下去的那一代快照。新导入技能换了一代不算退场，旧的那一代里没有要撤的东西，用着它的会话下一回合自然换。

1. **提交**（上表的 ③ 或 ⑦）。这之后拼的 `SessionSpec` 里没有它。
2. **会话线表登记退场**（`SessionLines::revoke(Retired{runtime, mcp_servers, snapshots})`，交付方 T10a，约定见第 11 节）。在表自己的锁里做两件事：把这批退场对象并进「已退场」集合；挑出绑定项引用了它们的会话线，**在跑回合的和空闲的都算**。登记一条新会话线时在同一把锁里看这个集合：绑定项里有已退场的 → 不登记，当场 `retire()`，这一回合以「会话约束与快照不一致」失败（现成的原因）。「看集合」和「登记」在一段锁里，撤回要么排在它前面、要么排在它后面，没有漏过去的。
3. **逐条停掉**（各条并行）：有回合在跑 → 走现成的取消（提交 → `stop_accepting()` → `cancel()`，T06 方案 2.6 第 4 条），回合以用户取消收尾（移除是用户点的）；然后 `retire()`，也就是 `session.terminate()` 确认整棵进程树清空再放掉会话（T06 方案 2.6 第 1、4 条；3.1b 停别的会话用的同一个接缝）。MCP 服务是 CLI 的子进程，跟着这棵树一起结束。
4. **时限与失败**：每条会话的 `terminate()` 用它自己的时限（T06 方案 5.4），撤回不另设更长的等待，所以整步有上界。清不掉 → 这条会话线记「旧树未确认清空」（T06 现成的标记：这个对话下次开会话之前会再清一次，还清不掉就不开，回合以 `Failed`「运行时进程树没能结束」收尾），写一条审计（对话 id、原因）。命令照样成功：第 1 步已经挡住了新的。
5. **删对象**：钥匙串里退场 MCP 的条目。退场的那一代快照留到下次启动清扫。
6. **管不到的**：MCP 程序自己另起的、脱离了进程组的后代（T06 实测 G7e：命令会脱离 CLI 的进程组），`terminate()` 杀不到；它们已经拿到手的密钥收不回来，只能轮换（L11）。

### 3.6 开会话：导入的东西怎么到 CLI 手里

1. **后台拼 `SessionSpec`**（T10a 的接线里加两行，读投影）：`plugin_dirs` = 当前这一代快照的各个插件子目录（这个运行时记着「快照损坏」时为空）；`mcp` = `Ready` 的那些 MCP 的 `McpServerRef`，带着每个键的当前版本。约束里的只读区 `imports/` T10a 本来就要填。
2. **适配器**（`iwork-agent-acp`）：去掉 `client.rs:174` 的报错。新模块 `mcp.rs`：对每个 `McpServerRef`，从 `SecretStore` 取 `launch` 和每个键那一版的值，拼成 ACP 的 `McpServer`（stdio：名字、命令、参数、环境变量；http / sse：名字、地址、请求头），放进 `session/new`、`session/load` 的标准字段 `mcpServers`。
   - `SecretStore` 在适配器构造时注入（泛型参数，后台组装）。
   - 每次取值限时 10 秒（钥匙串可能在等用户点系统弹框）。取不到、超时、钥匙串里那份解不出来 → 开会话失败，`AgentError::Protocol{"MCP「<名字>」的配置或密钥取不到（<键名或 launch>）"}`，不带值。不悄悄少挂一台：审批看到的清单和 CLI 实际加载的要是同一份。读到的引用刚被换掉或撤回时也是这个错，再开一次就好（3.4「先后怎么排」）。
   - 这段代码里不打日志、不 `{:?}` 请求；值只存在于这次调用的局部变量和发给桥接的那条消息里。
3. **桥接**（`iwork-bridge-claude`）：`Setup` 多一项 `mcp_servers`（值包在一个 `Debug` 只打印 `<redacted>` 的类型里）；`settings::mcp_json(&servers)` 生成 `{"mcpServers": {名字: {...}}}`，每台服务的值写在它自己的 `env` / `headers` 下；文件 0600，在会话目录里（T06 方案 3.3）。**值不进 CLI 的环境变量**：进了环境，CLI 起的每条命令、每个 hook、每台别的 MCP 服务都看得到。
   - 这个文件带着密钥明文，寿命和怎么收窄等 PD-4。T06 方案 3.3「残留的只是不含密钥的设置文件」那一句要跟着改（第 8 节）。
4. **会话内容核对多看一项**（`cli/facts.rs::check_content`，T06 方案 3.5 留的口）：`init.mcp_servers` 里每一项的名字都得在这次给的名字里，多出来 → `isolation_broken`（种类「MCP」，带名字），之后照 T06 方案 3.1b 停用运行时。给了而没连上的（状态不是 connected，或出现在 `mcp_server_errors` 里）不算隔离失效，记一条诊断（只有名字和状态），会话照开（L7）。
5. **本机验证与隔离重验带着当前的导入一起跑**（T06 方案 10.1、3.1b 第 6 条；它们用同一个 `build_launch`）：导入的插件目录让核对过不了时，在验证那一步就报出来，移除导入之后再验就能恢复。交付方 T06 S8 / T10a（第 11 节）。

### 3.7 首次提示

- 「提示过没有」只由 `LocalImportPrompted` 事件决定。它在两处产生：`ImportLocalConfig` 成功（同一次提交）、`DismissLocalImportPrompt`。
- 客户端连上之后看 `GetRuntimeStatusResult.import_unprompted`；里面有这个运行时、它又是就绪状态 → 调一次 `ListLocalConfig`；`prompt_due` 为真 → 弹首次导入框。`prompt_due` 是后台算的：没提示过，并且至少有一项导得了。
- 本机什么都没有时不弹，也不记「已提示」；以后有了东西，下次打开客户端会弹一次（等 PD-8）。
- 提示过之后，iWork 只在用户打开「从本机导入」时才去读用户的 Claude 配置。
- 设置 › 运行时 的「从本机导入」走同一个 `ListLocalConfig`，不看 `prompt_due`，不弹窗、不显示红点。

- 「导入所选」分两步发：先 `ImportLocalConfig`，从回来的 `LocalConfigImported` 事件里拿到每台 MCP 的 `mcp_server_id`，再逐个键发 `SetMcpSecret`，**一个发完、收到结果再发下一个**。输入框里的值只在这两步之间留在网页内存里，发完清空；不进 `ViewPatch`、不进 client-core 的 store、不进任何本地存储。`SetMcpSecret` 失败 → 这台 MCP 停在「缺密钥」，设置页能补填。因为 `mcp_server_id` 对应的启动配置写了就不改，值不会落到别的配置上。
- 移除的确认框写明「正在用它的会话会被停下」（文案问设计窗口）。
- 网页不做判断：能不能勾、弹不弹、显示什么状态文字，都是 client-core 照后台给的字段算好的。

## 5 出事场景

每条写三件事：会出什么事 / 怎么止血和回退 / 由什么保证。

**C1 导入时把用户的密钥读进了数据库**
- 出什么事：解析的代码被改坏，`env` 的值被当成普通字段留了下来；或者 PD-1 选了 b，`args` 里的连接串（`postgresql://用户:口令@…`）、`url` 里的密钥随 `LocalConfigImported` 进了事件。事件只追加不修改，进去了就洗不掉。
- 止血：第一步轮换那份密钥。然后移除这台 MCP（`RemoveImportedConfig`），用着它的会话被停下，之后的会话不再带它。事件里那一条留在库里；M1 只有产品负责人自己用、库不外传，修好后发新版，库里那条记进已知问题。要彻底清掉只能删库重来。
- 保证：R1、R2 的测试。`imported_values_only_in_secret_store` 是合入门槛，搜的是库文件的原始字节。

**C2 用户填的密钥进了日志或事件**
- 出什么事：有人在受理函数里加了一行 `debug!(?cmd)`，prost 生成的类型 `Debug` 会把 `value` 打出来；或者开发构建开着帧日志。
- 止血：轮换密钥；删日志文件（`<数据目录>/logs/`，删了不影响运行）。修掉那一行发新版。
- 保证：R3；`frame_display_redacts_listed_fields`；日志的字段名黑名单（已有，`logging.rs:42`）只是第二层，不当主要手段。

**C3 导入的技能带进了 hook、给自己放行了工具，或者一加载就执行命令**
- 出什么事：① 来源插件带 `hooks/hooks.json`，原样复制的话每条成员会话都会在沙箱外、不经审批地跑它。② 技能的 frontmatter 里写了 `hooks`，技能一被调用就注册。③ 写了 `allowed-tools: Bash`：平时 iWork 的 hook 照样判，放宽不了；但 CLI 自己跳过 hook 的那一刻（AGENTS.md 安全不变量第 2 条的已知限制），这个技能激活期间的 Bash 可能照 CLI 的规则直接执行，已知限制的范围就从「工作目录内的读」变大了。④ 正文里有 `` !`命令` ``，技能加载时执行；去掉 `allowed-tools` 之后，只读命令多半照样执行（3.2）。
- 止血：移除那个技能或插件：用着它的会话被停下（撤回），之后的会话里没有它。①② 已经跑过的 hook、④ 已经读进上下文的内容，iWork 收不回来，只能人去查。
- 保证：①：R4。②③：R5 加实测 K2。④：实测 K3 加 PD-5；这一条没定、格子没过，`SKILL_IMPORT_ENABLED` 不开，技能进不来。
- 这四样对**仓库里自带的技能**同样成立（需求 8.4 写的是照常加载）。那是改动前就有的问题，审查记为 `2026-11-12-m1-t10f-plan/1/F-8`，supervisor 已经交给 T06 与产品负责人；本方案只引用它，不解决。

**C4 技能目录里的链接或密钥文件被复制进了只读区**
- 出什么事：技能目录里有一个指向 `~/.ssh/id_ed25519` 的链接；作者把服务的私钥、`.env`、`credentials.json` 放在技能目录里；或者 token 写在一个普通名字的 `config.json` 里。复制过去之后，所有项目、所有助手的 Agent 不经询问就读得到；`~/.claude/` 原本在敏感目录里，Agent 读它是要问的。
- 止血：移除那个技能（用着它的会话被停下，新一代快照里没有它）；重启后台，清扫把旧的那一代删掉；等不及就手动删 `imports/<kind>/g-…` 里那个文件。轮换那份密钥。
- 保证：链接、私钥、范围内的凭据文件：R6，端到端那一条是放开门槛的条件。范围外的认不出：这是 PD-9 要产品负责人接受的例外，接受之前技能导不了（`skill_items_rejected_while_gate_closed`）。

**C5 导入之后被改**
- 出什么事：① Agent 想改导入的技能，让以后每条会话都带上它写的指令。② iWork 自己重导时就地改文件，在跑的会话读到半新半旧的技能。③ 复制到一半后台崩了，半份技能被下一条会话加载。
- 止血：① 被拒，不用止血。②③ 要是真发生：移除再导入一次，生成新的一代。
- 保证：①：R8。②③：R7。
- 挡不住的：不在沙箱里的同用户程序（导入的 MCP 服务、用户批准的沙箱外命令）改导入区、改数据库（L5）。不为它加防篡改的校验：校验用的摘要也只能放在同一个数据目录里，改得了文件的程序同样改得了它。（启动时核实 `MANIFEST` 管的是掉电之后缺文件，不管这个。）

**C6 导入的 MCP 越权，要立刻撤回**
- 出什么事：① MCP 服务进程不在沙箱里，以用户身份跑，每条会话一启动就起来，不经审批（需求第 9 章已知限制）。用户发现某台 MCP 不对劲，点了移除，可是已经起来的那几条会话里它还在跑。② 工具的「只读」是服务自己说的。③ 用户把名叫 `github` 的 MCP 换成了另一个程序，以前记住的「`mcp__github__create_issue` 不再问」接着对新程序生效。④ `~/.claude.json` 里某台 MCP 的命令被别的程序改了：用户在预览里看到的是原来那份，点导入的时候已经被换掉；或者用户点了重新导入，新命令拿到旧密钥。
- 止血：移除那台 MCP。移除做的事按先后是：提交（新会话拿不到）→ 停掉所有引用它的会话，在跑回合的和空闲的都停，CLI 连同 MCP 进程一起结束 → 删它在钥匙串里的条目（3.4「撤回」）。有会话的进程没能确认结束时：那条对话的回合以 `Failed`「运行时进程树没能结束」收尾，审计里有一条，这个对话下次开会话前会再清一次。然后轮换交给过它的密钥；到设置里撤销它名下记住的规则（PD-7 选 a 的话已经一起删了）。
- 保证：①：R16 的演练 `revoke_drill_active_idle_and_opening_sessions`（假运行时。三条对话：甲的回合正在等审批，乙空闲但会话活着，丙的会话正开到一半、还没登记；另有丁，它的会话是在这台 MCP 导入之前开的，绑定项里没有它。移除这台 MCP 之后：甲的回合以取消收尾、会话 `terminate()` 过；乙的会话 `terminate()` 过；丙登记时被认出来、当场 `retire()`，没有进入「在跑」；丁原样不动；撤回之后新拼的 `SessionSpec` 里没有它；这些都发生在删钥匙串条目之前。再跑一遍让乙的 `terminate()` 返回失败：命令照样成功，审计里有乙，乙的会话线记着「旧树未确认清空」）。脱离了进程组的后代停不掉，是边界（L11）。②：M1 所有 MCP 工具都询问（PD-6），不依赖这个声明。③：等 PD-7。④：R17、R12。

**C7 用户改了自己的 Claude 配置，iWork 这边没跟上**
- 出什么事：用户更新了一个技能，或者改了某台 MCP 的参数，iWork 里跑的还是导入那一刻的样子；用户以为改了，结果没生效。反过来，用户在 Claude Code 里删掉的 MCP，iWork 里还在跑。
- 止血：打开「从本机导入」，条目上标着「来源有变化」或「来源不在了」，重新导入或移除。
- 保证：`sync_reports_changed_and_missing_sources`（技能改一个字节、MCP 改一个参数、来源整个删掉各一例）；`sync_unspecified_when_secret_store_unreadable`；`rebuild_preserves_sync_state`（R20）。导入是复制一份快照，不自动跟随，这是定下来的做法（技术设计 9.5 第 4 条写的是「复制进」）。

**C8 导入的东西让所有会话都开不了**
- 出什么事：① CLI 报的插件 `path` 和 iWork 给的目录对不上（比如 CLI 把路径解析成了别的写法），每条会话第一轮都被判成隔离失效，运行时停用（T06 方案 3.1b）。② 某台 MCP 的程序起不来或很慢，每条会话的第一轮都要多等，最多 30 秒。③ 钥匙串取不到某个值，带这台 MCP 的会话全部开失败。
- 止血：都是同一步：移除惹事的那一项（①③ 的错误文字里有名字；② 看诊断里哪台没连上）。① 之后在运行时详情页点「重新验证」，隔离重验带着当前的导入跑，过了就恢复。全部移除等于回到没有导入的状态，那是 T06 验过的配置。
- 保证：R16；演练 `bad_import_drill`（T06 方案 15.1 的假 CLI，经真实的后台、适配器、桥接：导入一个技能，假 CLI 把这个插件的 `path` 报成别处 → 隔离失效、运行时停用 → `RemoveImportedConfig` 成功 → 重新验证通过 → 会话开得了）。① 的预防：实测 N1 没过之前步 6 不合入。

**C9 钥匙串出问题**
- 出什么事：① 这台机器没有可用的钥匙串（Linux 上没有 Secret Service）。② 后台是没有界面的进程，钥匙串弹了「允许访问」的系统框没人点。③ 升级 iWork 之后签名变了，钥匙串不认新程序，每次读都弹框。④ 用户在「钥匙串访问」里手动删了条目。⑤ 填值填到一半，钥匙串写成了、提交没成。
- 止血：①：`SetMcpSecret` 报 `SECRET_STORE_FAILURE`，带系统给的原因；不用密钥的 MCP 在 PD-1 选 a 时同样导不了（启动配置也在钥匙串里），技能不受影响。②③：取值限时 10 秒，超时开会话失败并点名；用户点了「始终允许」之后重试。④：开会话失败并点名；到设置里重填那个键，或移除重导。⑤：什么都不用做，生效的还是上一版；界面报了错，用户再填一次。
- 保证：R13、R18；`secret_store_contract`（同一组用例对假实现和真钥匙串各跑一遍：存、取、删、取不存在的、删不存在的）；实测 H1–H3。

**C10 带密钥的 `mcp.json` 留在了盘上**
- 出什么事：桥接被 `SIGKILL`（取消、等待上限、后台崩溃都会），会话目录没删，里面的 `mcp.json` 带着密钥明文。
- 止血：下一次桥接启动时的清扫会删（T06 方案 3.3）；等不及就手动删 `<数据目录>/run/h/` 下的目录（没有会话在跑时删了没有影响）。这个目录 Agent 读不到；读得到它的是不在沙箱里的同用户程序，它们本来也读得到用户自己 `~/.claude.json` 里的同一份密钥。
- 保证：已有的 `sweep_removes_only_dead_owners_dirs`（`session_dir_tests.rs`）；PD-4 定了之后的那一条。

**C11 加了新的事件种类，旧版本读不了库**
- 出什么事：发了带 `ImportedConfigRemoved` 的版本之后想退回上一版，旧程序见到不认识的事件，以退出码 12 停下（T04 方案 S8）。
- 止血：只能向前修（T07 的 PD6，产品负责人 2026-11-10 定）。
- 保证：T10a 验收 4（真引擎读到不认识的事件种类时后台以 12 退出、数据不动）。

**C12 导入和移除撞在一起**
- 出什么事：两个客户端窗口，或者一次重试，让「导入 B」和「移除 A」同时在做。导入那一条是在 A 还在的时候算的：它建的新一代快照里有 A，它要提交的条目清单里也默认 A 在。它后提交的话，刚移除的 A 又回来了，而用户以为已经撤掉。
- 止血：真发生了就再移除一次（会再走一遍撤回）。
- 保证：R19。后提交的那条被写线程拒掉，它建的那一代没人引用。

**C13 导入时掉电**
- 出什么事：只做了改名、没有 `sync` 的话，掉电之后可能是「事件已经在库里、新一代的目录项在、文件内容是空的或缺的」；启动清扫再把上一代删掉，技能就整个没了，会话加载到半份技能。
- 止血：真发生了：列表里标着「快照损坏」，重新导入一次。旧的各代目录这时都还在盘上（没清扫），要找回某个文件可以人手去拿。
- 保证：R7 的掉电注入与 `startup_verifies_current_before_sweeping`。

## 7 性能（需求第 14 章）

- 不在热路径上：事件推送、帧合并、存储写入、hook 都没动。`import_revision` 的核对只在三种导入事件的投影里多一条带条件的 `UPDATE`，别的事件不多执行任何语句。
- 开会话多出来的：每台 MCP 一次钥匙串读加每个键一次。步 2 验收时在 macOS 上量单次读的耗时，记进完成记录；单次超过 50 毫秒就回来商量要不要一台服务合成一条。
- 带 MCP 的会话，CLI 要等服务器连上才跑第一轮，文档说最多 30 秒。这段时间不在 iWork 自己的进程里（第 14 章只统计 iWork 自身进程），但用户感觉得到；M6 量出来之后写进运行时详情的说明。
- 发现：读一个可能有几 MB 的 `~/.claude.json`（流式解析，别的键跳过），加上把每个技能的文件读一遍算摘要（本机 41 个技能约 13 MB）。只在首次检查和用户打开导入入口时做。步 3 验收时在本机配置上量一次，记进完成记录；超过 500 毫秒回来商量（摘要不能挪到勾选之后：指纹要它）。
- 导入：复制文件，每个文件一次 `sync`。本机 41 个技能约几百个文件，macOS 上开着 fullfsync 时可能要几秒。一次性的操作，界面上是一个等待态；步 4 验收时量一次记下。
- 启动恢复：对当前这一代的每个文件 `stat` 一次，不读内容。

## 9 已知限制（请产品负责人知情；定稿后由 supervisor 请他登记进需求第 9 章）

这一节只放**不放宽安全不变量**的缺口。放宽不变量的两处不在这里，在 PD-1（参数与地址）和 PD-9（技能文件），要明确接受才启用。

- **L1** 导入的 MCP 是完全受信任的程序：不在沙箱里，读得到 iWork 的数据目录和它继承到的环境变量（含 hook 通道的令牌）。和需求第 9 章「MCP 服务进程不在沙箱内」是同一条，导入框上要说清。
- **L2** 技能导入后和在 Claude Code 里不完全一样：`allowed-tools`、`hooks`、`model`、`effort` 被去掉；名字多了前缀（用户级技能变成 `imported:<名>`）；名字以 `.` 开头的、范围表里的文件不带；插件里的技能要是用到插件根目录下 `skills/` 之外的文件（脚本、`bin/`），导入后找不到。
- **L3**（第 1 版在这里写的「技能目录里的密钥文件只认私钥表」挪走了：它放宽了不变量，改成 PD-9。）
- **L4** 插件自带的 MCP 留在用户的插件目录里跑：插件更新或卸载会改变、弄坏它，iWork 这边看到的是「来源有变化」或连不上。
- **L5** 不在沙箱里的同用户程序（导入的 MCP、用户批准的沙箱外命令）改得了导入区和数据库，iWork 不校验。和会话目录里的设置文件是同一类（需求 v1.73）。
- **L6** 钥匙串里可能留下不再用的条目（撤回或换版本时删失败、命令崩在提交之前、提交被拒后清理失败）。它们没被任何引用指着，iWork 不会再读；删失败的名字在审计里；要清得用户自己到「钥匙串访问」里删。
- **L7** 导入的 MCP 没连上（程序不在、密钥不对、超时）时，M1 的界面没有提示，只有诊断日志；模型会说它没有那个工具。
- **L8** 要 OAuth 登录的远程 MCP，iWork 里登录不了；连不连得上看用户有没有在自己的 Claude Code 里登录过（M7）。
- **L9** 用户填的值里有 `${…}` 时会被 CLI 当成环境变量引用（M5 量过之后定写法）。
- **L10** 导入框上显示的启动方式是从用户配置里现读的，里面要是写着密钥，会显示在屏幕上，也会经过本机的进程间通道（不落盘；开发构建的帧日志里遮掉）。它随 PD-1 一起定。
- **L11** 撤回停得掉的是 CLI 的进程树（含 MCP 服务本身）。MCP 程序自己另起的、脱离了进程组的后代停不掉；已经交到 MCP 程序手里的密钥收不回来，只能轮换。
- **L12** 撤回停掉的回合照用户取消收尾，没做完的那一步不会自动续上；用户再发一条消息，新会话里没有被移除的东西。

## 12 需产品负责人决定

**PD-1 MCP 的启动配置（命令、参数、地址）存哪；接不接受 iWork 读它、存它**
- 问题：参数和地址里可能写着密钥（数据库连接串 `postgresql://用户:口令@…`、地址里带 key 的远程 MCP），iWork 不读值就分不出来。要导入 MCP，这几样又非读不可。所以不管存哪，iWork 都读了、存了、在导入框上显示了可能带密钥的内容，这放宽了安全不变量第 1 条，要明确接受。任务卡和技术设计 9.5 写的是存数据库：存了就进事件，事件只追加不修改，进去了洗不掉，验收 1「数据库里搜不到密钥明文」对这类 MCP 不成立。
- a（推荐）接受例外，范围是：参数和地址读进内存、整份存进系统钥匙串、导入框上显示一次；数据库、事件、日志里没有。代价：没有钥匙串的机器上，不带密钥的 MCP 也导不了；开会话每台 MCP 多读一次钥匙串。
- b 照卡片原文存数据库。代价：上面说的那类 MCP 的密钥进库、洗不掉；例外的范围大得多，导入框上要提示「参数和地址会原样保存」。
- c 加一段识别「看上去像密钥」的规则，命中的不让导。代价：一套靠猜的新规则，会漏也会误伤，不推荐。
- d 不接受：M1 不导入 MCP 的启动配置，用户在 iWork 里手填命令和参数。代价：FR20 的 MCP 部分变成手工录入。
- 卡住：`MCP_IMPORT_ENABLED`（步 5 放开 MCP 条目）、步 6 里取启动配置的那一段。

**PD-2 环境变量和请求头的值，要不要一律重填**
- 问题：FR20 写的是密钥由用户重新填写。iWork 不读值，分不出哪个是密钥，所以只能每个键都让用户填。产品负责人本机那 3 台 MCP 的 4 个环境变量，看键名都是路径和开关，也得手抄一遍。
- a（推荐）一律重填，照 FR20。代价：手抄。

**PD-9 技能目录里的凭据文件：边界划在哪，范围外的接不接受**

- c 不接受：M1 不做技能导入，只导 MCP。代价：FR20 的技能部分、验收 1 里「导入的技能出现在 `init`」M1 不满足，要改任务卡。
- 卡住：`SKILL_IMPORT_ENABLED`（步 5 放开技能与插件条目）。

## 13 ADR（developer 随组 B 写入 `docs/adr/`，编号合入时定）

### ADR-T10f-a 导入只搬名字和形状；值进钥匙串，技能按白名单重拼成不可变的快照

- **背景**：要把用户本机 Claude Code 的 MCP 与技能搬进 iWork，同时守住三条：不读用户已有的凭据；用户的 hook 与放行规则不进成员会话；导入的东西 Agent 改不了。用户的配置文件里密钥和普通配置混在一起，插件目录里技能和 hook 混在一起，CLI 自动加载的位置还会随版本增加。
- **决定**：① 发现只打开一张来源表里的文件、只取表里的键；`env`、`headers` 的值在解析时丢掉，由用户重填。② 从 MCP 配置读出来的值，除了名字和键名，只进系统钥匙串；数据库和事件里没有启动配置。③ 导入区里的插件目录由 iWork 自己拼：只放技能目录，清单自己写，`SKILL.md` 的 frontmatter 只留白名单里的键，看不懂的不导；凭据文件范围内的不带。④ 重新导入一台 MCP 等于换一台，密钥重填。⑤ 放宽「不读取、不保存凭据」的两处（参数与地址、范围外的技能文件）各有一个默认关着的门槛，产品负责人明确接受之后才开。
- **备选与放弃原因**：把启动配置存数据库（任务卡原文）：参数里的密钥会进洗不掉的事件。读出值再判断是不是密钥：判断本身就读了凭据，而且靠猜。复制整个插件再删掉 hook：删的是认识的那几种，CLI 多一种自动加载的位置就漏。把认不出的凭据文件登记成已知限制就上线：那是放宽不变量，不是限制。
- **影响**：多一个事件种类（只能向前修）；没有钥匙串的机器上 MCP 导不了；技能导入后和在 Claude Code 里不完全一样（第 9 节 L2）；以后接 Codex、agy 的导入，写一个 `LocalConfigSource` 的实现，沿用同一套命令、存储和钥匙串的名字规则。

### ADR-T10f-b 事务之外的对象：写一次带版本、先持久后引用、提交时核对、退场先挡后停再删

- **背景**：导入要写文件和钥匙串，它们不在数据库事务里。只说「先写对象、后提交事件、崩了清扫」不够：原地覆盖的对象在提交之前就被会话读到了；两条命令穿插时，算在前面、提交在后面的那条会把别人的结果盖掉；用户确认的和实际存的是两次读；改名不等于持久；移除只改了配置，已经起来的进程还在跑。
- **决定**：3.4 的四条约定。① 会话读得到的对象（快照、启动配置、键的一版值）写一次、名字带版本。② 对象持久化之后才提交事件，事件是唯一的切换点。③ 改动导入状态的事件带 `base_revision`，由写线程核对；用户确认的内容带指纹，受理时对来源只读一次。④ 退场先提交、再停掉引用它的会话与进程、最后删对象。
- **备选与放弃原因**：只靠应用层的一把锁：锁管不到以后多出来的调用方，也证明不了；锁留着只为排队。固定名字的钥匙串条目加「提交失败就写回旧值」：写回本身会失败，中间那一段会话读到的已经是新值。保存之后再让用户确认一遍最终配置：多一轮交互，指纹绑定已经保证了存的就是看的。移除只影响下一回合：出事时等不起。
- **影响**：三种事件各多一个字段；投影判状态多一处（知会 T02）；钥匙串里一个键可能短时间有两条；T10a 的会话线表要提供 `revoke`；以后再有「事务之外要落东西」的命令，照这四条写。
