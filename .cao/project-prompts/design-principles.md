# 设计原则

出稿和审查实现出来的界面都按这一份。出稿和审查是两个互相独立的角色，项目可以只有一个；这份原则是两边共同的参考，不是一边对另一边的要求。它写的是任何项目都成立的原则；本项目自己的规范、token、组件库和现有页面优先于它，用户原话和验收条件又优先于规范。项目要追加自己的规则，写进自己角色的项目提示词（`.cao/project-prompts/<角色 id>.md`），不改这份。

## 先判断做多重

目的是把功夫花在对的地方：一个排得好的朴素页面总能过，过度设计的常常不能。

- **实用型**：后台、看板、工具、表单、设置页、编辑器，还有文档、备忘、内部说明这类内容页。绝大多数任务是这类，后端项目里唯一的那个管理页面也是。功夫花在信息设计、层级、密度和一致性上：字号阶梯准、间距有节奏、颜色少而准、每个元素都有活干。不要大头图，不要装饰性背景，不要为了「有设计感」加东西。
- **有主张**：对外的落地页、品牌页、活动页，用户会留着用或分享出去的页面。要有一个说得出名字的方向和一处让人记住的东西，在对作品有帮助的地方冒一次视觉上的险。
- 需求没说就按实用型做。

## 从题材取材

- 风格从题材自己的行业、材料和用语里来：给小学生的玩具和给分析师的报表，长得应当完全不同。至少放一处只有这个题材才有的细节，当内容用，不当装饰：它真实的单位和刻度、它的术语、它的文档惯例。
- 文案和数据用真实内容，不用「示例标题」「Lorem ipsum」「欢迎来到」。示例数据要像真的：数量级对，长短不一，带上极端值（很长的标题、很长的 ID、0 条、很大的数），布局问题靠它们才暴露。
- 不复刻别家专有的或受版权保护的界面。用户说「像 X 一样」，去弄清他想要的是什么（密度、流程、某个交互），只借思路和结构，不抄它的品牌、配色、图标和文案。
- 风格谁说了算：用户原话和验收条件 > 项目设计规范和定稿 > 现有页面的视觉语言 > 这份原则 > 自己的选择。项目没有规范、没有可沿用的页面（比如后端项目第一次加管理页），就按这份原则和题材自己定，并写明没有可沿用的东西。

## 页面是界面时

后台、看板、列表、表单、编辑器是被扫视、被操作的，不是从上读到下。功夫从排版转到信息设计。先问读者打开这页要做什么决定、做什么操作，第一屏就回答它；一个等着输入的空壳什么都说明不了，页面一打开就是真实的工作状态。

对所有界面都成立的：

- **先摘要后细节。** 摘要是「有几件事要我做、最急的是哪件、点哪里开始」，不是把所有分区平铺。0 条的分组收成一行或并进摘要，不给它一个和有内容的分组一样大的标题。
- **状态三重编码。** 进度、风险等级、处理结果这类状态，用形状（圆点、胶囊、色条）加颜色加文字一起表达，需要注意的东西一眼看到。语义色（成功、警告、错误、信息）和品牌强调色是两回事，语义色不算强调色。
- **同类的多条记录用列表或表格，不堆成同款卡片。** 三条以上就用列表。列的顺序按读的顺序：先标题后 ID，数字右对齐并用 `font-variant-numeric: tabular-nums`。长串字段（ID、路径、哈希、邮箱）要有截断或换行策略，手机宽下一定要看。
- **每行、每个区块只有一个明显的主操作**，次要操作弱化，危险操作放远一点并要确认。按钮文案写结果（「归档」「重新发送」），不写「确定」「提交」。
- **能点的看着就能点**，用真的 `<a href>` 和 `<button>`；hover 和 focus 有可见的样式。
- **密度按扫视定，不按阅读定。** 界面的行高、留白比文章紧；不用大留白装「高级」。
- **导航要能看出现在在哪、还有哪些地方**；筛选、排序、搜索放在数据上方同一行，当前筛选状态看得见。
- 有图表就按比例画：每个标签对应图上真到得了的值，淡网格，终点突出，两套主题下都看得清。

按界面类型再多看一眼：

- **看板、总览页**：先回答「现在怎么样、哪里不对」。指标要带对比（和上期、和目标），光一个数字说明不了好坏。
- **列表加详情**：列表只放做判断要看的几列，别的进详情；详情页把最常要核对的事实排在最上面，操作跟着事实走。从详情回列表的路要看得见。
- **表单和设置页**：按用户的任务分组，不按数据库字段分组；每个字段写清填什么、填错会怎样；必填和可选分得出来；保存按钮在哪、保存了会发生什么，不用猜。
- **编辑器、工作台**：正文区最大，工具围着它；常用工具近，少用的收起来；当前选中的是什么、有没有未保存的改动，一直看得见。

## 页面是内容时

落地页、文档、营销页、说明页是从上读到下的。功夫回到排版和节奏：读的顺序、段落的长短、第一屏放什么。处理的分量按「先判断做多重」分：

- **实用型内容**（文档、备忘、内部说明）：把它做精致就够了，真正的字号层级、讲究的间距、像样的配色；不要为它造一个大头图，点缀要有品位、要少。
- **有主张的内容**（落地页、品牌页、活动页）：第一屏用这个题材世界里最有代表性的东西开场，一句话讲清价值，一个主要行动，整页反复出现的是同一个行动，不是三个互相竞争的按钮。证明（评价、数字、客户）只用用户给的材料，没有就标「待填写」，不编。
- 内容页也要在手机宽下能读：标题不出现难看的断行，多栏在窄屏折成一列。

## 卡片和装饰按角色用

边框、底色、圆角、阴影，每一样都在对读者说「这是一个单独的东西」。按角色给：只给真需要独立出来的那一个元素，比如正在等人决定的那条、当前选中的那项。

- 一页里只有一种卡片样式；卡片里不套卡片；不是每个分区都要一个框。
- 层次靠字号、字重、位置和间距建立，不靠给每块加框加阴影。
- 只有那些数字就是页面重点时，才用一排大数字卡开场。
- 装饰只留为需求服务的；做完挑出一处多余的装饰删掉。

## 排版和间距的基本功

- 字体一两族就够，标题和正文要刻意搭配；只能用系统字体栈时，页面的性格靠字号阶梯、字重、字宽和对比来做。定一套字号阶梯并守住它；标题和正文的字重、字号差距要看得出来。中英混排时，拉丁字母和数字的字体要和中文配，不能一处黑体一处衬线。
- 同级元素用 flex 或 grid 加 `gap` 排，不给每个元素单独加 margin，那样会悄悄重叠或加倍。
- 任何宽度下两侧至少留 16px；手机宽（约 400px）下行换行或叠成一列，不出现横向滚动。
- 重复的元素要一致：一排卡片、一列「标签：值」、兄弟元素上的徽章，边缘、基线、内边距都一样，反复出现的元素放在每一项的同一个位置。
- 容器高度由内容决定；可能撑破的文字要在自己的容器里换行或滚动。文字被截掉、元素重叠、字体退回备用，都是 bug。
- 中性灰略带一点强调色的色相，纯中灰显得没花心思。纯白和近黑当背景都可以，但得是为题材选的。
- 标题加 `text-wrap: balance`；正文行距比标题宽松。
- 页面静止时就是完整的：所有要读的内容打开就看得见，不靠动画入场。

## 两套主题

浅色和深色都要设计，深色和浅色花一样的心思，不是反个色：背景和文字各自重选，强调色和语义色在两种底色上都要成立，对比度都要够。只有刻意只走一种视觉世界（霓虹街机屏、活版印刷请柬）才可以只做一套，并写明这是有意的选择，不是漏了。产品已经有主题切换的，两套都要看。

## 避开 AI 味

下面这些不是不能用，而是不管什么题材都会冒出来的默认值。需求点名要的照做，没点名就别把自由度花在它们上面。

配色套路：
- 紫蓝或暖陶土色的渐变头图；渐变 wash 当装饰；
- 暖米色底 + 高对比衬线标题 + 陶土色强调，这一整套；
- 近黑底 + 一个荧光绿或朱红强调色；用 `#0B0B0B`、`#111` 这类偏色近黑代替黑；
- 浅色稿反个色当深色稿。

结构套路：
- 内容切成一模一样的卡片，所有卡片同一个圆角、同一层淡灰阴影；圆角卡片左侧加一根强调色竖条；
- 不是序列的内容编号（`01 / 02 / 03`、`01 //`）；细线分隔、零圆角、报纸式的密排多栏；
- 一排大数字指标卡开场，而数字不是页面重点；
- 全部居中；每个区块都淡入上滑；
- 结构手段（编号、小眉题、分隔线、标签）只表达内容里真实存在的东西：内容真是步骤或时间线才编号。

字体和文案套路：
- 等宽字体当正文或当所有小标签；标题上方的全大写小标签；
- 用中点连起来的元信息（`A · B · C`）；`词 — 片段` 这种空格破折号标签；
- 链接和按钮末尾加箭头；标题里只给一个词换色或换斜体；
- emoji 当标题或图标；无意义的图标栅格；
- 「欢迎来到」「开始使用」「示例标题」这类填充文案。

稿子和说明里特有的：
- 为了演示加的「模拟加载」「模拟出错」按钮进了页面：状态要么是独立文件、要么是真实数据，不画开关；
- 说明里用「精致」「优雅」「现代化」形容自己，而说不出任何一个决定。

## 文案

文字是设计材料，不是装饰。站在用户这边起名字：用人认得的名字叫东西（人管的是「通知」，不是「webhook 配置」）。主动句，口语，具体优于聪明，短句优于压缩。

- 按钮写清点了会怎样（「保存更改」，不是「提交」）；同一个动作全流程用一个名字，按钮叫「发布」，提示就叫「已发布」。
- 报错说清出了什么事、怎么改，不道歉、不含糊。空状态引导下一步，不只说「暂无数据」。
- 每个文字元素只干一件事。

## 只在一处大胆

让一个元素成为记忆点，别处安静、克制。界面类页面的「大胆」通常是信息组织上的一个主意：把待办做成一条能逐个处理的队列，把做决定要看的事实排在同一行。不是视觉花活。

- 强调色和背景打架，往相邻色相挪一点或降饱和，不换色。
- 动效只留一个编排好的时刻；回应用户操作、说明发生了什么变化的动效不受这条限制。

## 质量底线

不用宣告，但要做到：

- 控件用真元素：`<button>`、`<a href>`、配 `<label>` 的 `<input>`。加了 `role` 的 div 看着一样，Tab 会跳过它。纯图标按钮加 `aria-label`；装饰性 SVG 加 `aria-hidden="true"`。
- 手机宽下点击目标不小于 44px。
- 正文和说明文字对比度不低于 4.5:1（24px 以上 3:1），两套主题都查。最常不达标的是说明文字的灰和白字下面的彩色底。
- 必须区分的颜色不只靠色相，还要有明度差；蓝和橙优先于红和绿。
- 键盘焦点看得见；尊重减少动效的偏好。

## 截图看渲染效果

目的：手机宽下导航断行、表格撑破、长串字段折成几行这类问题，不渲染出来根本看不见。出稿和审查都用下面这套：每个要看的页面截四张，桌面宽和手机宽，浅色和深色。截图放系统临时目录，不进仓库。

只需要 shell 和一个 Chromium 内核的浏览器（Chrome、Chromium、Edge 都行，参数一样），不依赖 node、python 或别的自动化工具。先找浏览器，macOS 看应用目录，Linux 看 PATH，都没有就不报错、照「截不了图时」处理：

```bash
CHROME=""
for c in \
  "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  "/Applications/Chromium.app/Contents/MacOS/Chromium" \
  "/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge" \
  "$(command -v google-chrome 2>/dev/null)" "$(command -v google-chrome-stable 2>/dev/null)" \
  "$(command -v chromium 2>/dev/null)" "$(command -v chromium-browser 2>/dev/null)" \
  "$(command -v microsoft-edge 2>/dev/null)"; do
  if [ -n "$c" ] && [ -x "$c" ]; then CHROME="$c"; break; fi
done
if [ -n "$CHROME" ]; then echo "浏览器：$CHROME"; else echo "没找到 Chrome、Chromium 或 Edge，照「截不了图时」处理"; fi
```

找到了就定义 `shot`，一个页面一次调用，地址可以是 `file://` 也可以是 `http://`：

```bash
OUT=$(mktemp -d "${TMPDIR:-/tmp}/ui-shots.XXXXXX")
shot() {  # 用法：shot <名字> <地址>
  "$CHROME" --headless=new --disable-gpu --hide-scrollbars --blink-settings=preferredColorScheme=1 --window-size=1440,1800 --screenshot="$OUT/$1-desk.png"  "$2" 2>/dev/null
  "$CHROME" --headless=new --disable-gpu --hide-scrollbars --blink-settings=preferredColorScheme=1 --window-size=400,1800  --screenshot="$OUT/$1-phone.png" "$2" 2>/dev/null
  "$CHROME" --headless=new --disable-gpu --hide-scrollbars --blink-settings=preferredColorScheme=0 --force-dark-mode --window-size=1440,1800 --screenshot="$OUT/$1-desk-dark.png"  "$2" 2>/dev/null
  "$CHROME" --headless=new --disable-gpu --hide-scrollbars --blink-settings=preferredColorScheme=0 --force-dark-mode --window-size=400,1800  --screenshot="$OUT/$1-phone-dark.png" "$2" 2>/dev/null
}
shot settings "http://127.0.0.1:3000/settings"
shot v1-orders "file://$PWD/docs/design/<任务 ID>/v1/orders.html"
echo "$OUT"; ls "$OUT"
```

- `--blink-settings=preferredColorScheme=1` / `=0` 把页面定成浅色 / 深色，不跟系统外观走（系统是深色时不加它，浅色那两张也会是深色）；深色那两行另加 `--force-dark-mode` 兜底。页面没做深色时四张里深色那两张和浅色一样，这本身就是一个发现。
- 截图只有窗口那么高；页面比 1800px 长就把高度调大。
- `ls` 出来每个页面应有 4 张，不对就去掉 `2>/dev/null` 看报错。
- 本机有别的截图工具（浏览器自动化 CLI、浏览器 MCP、项目自带的截图脚本）也行，截出同样的几张就行；汇报里写用的是什么。
- 页面要登录、要某个状态才看得到的，先按主管给的账号和步骤到那个状态，或者用主管给的地址直接打开那个状态；做不到的那几张标「未截」。

看什么：

- 手机宽：导航有没有断行、挤成竖排；表格和长串字段有没有撑破或横向滚动；按钮有没有挤在一起；两侧还有没有留白。
- 桌面宽：第一屏回答得了「我先做什么」（界面）或「这是什么、为什么值得看」（内容）吗；空白是不是太多，卡片是不是一叠一样；层级是靠字号和位置建立的，还是靠框。
- 深色：对比度够不够，语义色还分得清吗，是不是只是反了个色，还是根本没做。
- 两种宽度都看：有没有重叠、截断、字体退回备用（中文一处黑体一处宋体）。

截不了图时（没有浏览器、命令报错、你的工具读不了图片）：不要硬凑，也不要凭代码猜视觉结果。按自己角色模板里「截不了图」的处理走：出稿的在汇报第一行写明没看；审查的把对应条目标「未验证」。截到了图但看不了，把目录路径交给主管。
